# Dolby: стерео → surround → наушники

Здесь собраны DLL и результаты исследования цепочки:

```text
Стереомузыка 2.0
        ↓
Surround Decoder — создаёт 5.1 / 7.1
        ↓
Surround Virtualizer — применяет HRTF
        ↓
Два канала для наушников
```

## Что находится в папке

- `DolbyAudioProcessing.dll` — точная копия установленной библиотеки Dolby Audio Processing for Microsoft Spatial Audio, версия файла `7.3.7.rel`.
- `documents/Dolby-PCEE-v4-white-paper.pdf` — официальный документ Dolby, который прямо описывает такую цепочку.
- `evidence/binary-findings.json` — строки из установленных компонентов с байтовыми смещениями, SHA-256 файлов и экспортами DLL.
- `evidence/file-manifest.json` — версии файлов, исходные пути, контрольные суммы и наблюдение загруженных модулей аудиопроцесса.
- `inspect_dolby.py` — скрипт для повторения статического исследования. Читает файлы, не загружает DLL для исполнения и не меняет настройки Dolby.
- `SOURCES.md` — ссылки, границы выводов и дальнейшая проверка.

## Подтверждено документацией

В документе **Dolby PC Entertainment Experience v4**, страница 6, раздел **Surround Decoder**, описано преобразование обычной стереомузыки и матрично закодированного двухканального материала в 5.1 или 7.1. Результат может поступать на многоканальную акустику либо во внутренний Surround Virtualizer.

На странице 7, раздел **Surround Virtualizer (for built-in speakers or headphones)**, описано применение HRTF для воспроизведения существующего или созданного Surround Decoder многоканального сигнала через встроенные динамики либо наушники.

**Это документ про старое поколение PCEE v4. Он подтверждает существование цепочки у Dolby, но не устанавливает точную схему обработки текущего Dolby Access.**

## Что найдено в современной DLL

Исследованный пакет: `DolbyLaboratories.DolbyAccess_3.27.12250.0_x64__rz1tebttyb220`.

В `DolbyAudioProcessing.dll` найдены диагностические строки:

| Строка | Что она позволяет предположить |
|---|---|
| `dap_vr_surround_decoder_enable_set` | Есть настройка включения Surround Decoder |
| `dap_vr_virtualizer_front_speaker_angle_set` | Настройка угла виртуальных фронтальных колонок |
| `dap_vr_virtualizer_surround_speaker_angle_set` | Настройка угла виртуальных surround-колонок |
| `dap_vr_virtualizer_height_speaker_angle_set` | Настройка угла виртуальных высотных колонок |
| `dap_vr_output_mode_set` | Настройка режима обработки, числа выходных каналов и матрицы смешивания |
| `GetStereoBypassAllowed` | Есть логика разрешения обхода обработки для стерео |
| `ConfigureStaticChannelMetadata` | Есть работа с метаданными статических каналов |

Также найдены упоминания DAP-VR, OAR, AIDE, VLLDP и конфигурации статических каналов 7.1.4. **Одно упоминание 7.1.4 не доказывает апмикс стерео в этот формат.**

В `DolbyHrtfEnc.dll` найдены `StereoBypassMode`, `GetStereoBypassMode`, имя `Dolby.DolbyAudioProcessingModule` и ссылка на `DolbyAudioProcessing.dll`. Это связывает компонент для наушников с общей библиотекой обработки; точный граф вызовов не восстановлен.

При предыдущей проверке на этом компьютере `DolbyHrtfEnc.dll` и `DolbyAudioProcessing.dll` были загружены в `audiodg.exe`. Это подтверждает участие библиотек в аудиопроцессе, но не активность каждого содержащегося в них алгоритма.

## Отдельная HDMI/MAT-ветка

В `DolbyAccess.dll` есть свойства `ChannelUpmixerEnabled` / `IsChannelUpmixerAvailable`. В `DolbyMatEngine.dll` найдены `ConfigureUpmixer`, `GetUpmixerStatus`, `live_upmixer_set_prop` и `live_upmixer_get_prop`.

Это признаки управления Channel Upmixer в MAT-компоненте. Их нельзя автоматически переносить на режим Atmos for Headphones. Остальные DLL здесь не скопированы; в `evidence` сохранены сведения о них и релевантные строки.

## Что пока не доказано

- Что при воспроизведении Spotify текущий профиль Music включает Surround Decoder.
- Что стерео всегда превращается именно в восемь промежуточных каналов 7.1.
- Как распределены вычисления между внутренними модулями и в каких случаях используется stereo bypass.
- Что эта DLL позволяет отдельно вывести апмикс как обычный PCM 5.1/7.1 через публичный API.

`DolbyAudioProcessing.dll` — не самостоятельный плеер и не обычный VST-плагин. При исследовании обнаружены экспорты `DllCanUnloadNow` и `DllGetActivationFactory`; простого экспортированного метода вида `UpmixStereoTo71` не обнаружено.

**Рабочая гипотеза:** библиотека содержит управление Surround Decoder и виртуализатором, совместимое по смыслу с описанной Dolby цепочкой. Для доказательства её активности в текущем профиле нужны значения параметров во время обработки либо наблюдение промежуточного сигнала.

Различие звучания при включении Dolby само по себе недостаточно: его также могут создавать EQ, регулировка громкости, виртуализация фронтальной пары и другие эффекты.

Наш `DolbyAccessAutoProfile.exe` только выбирает профиль; аудиопоток через него не проходит.
