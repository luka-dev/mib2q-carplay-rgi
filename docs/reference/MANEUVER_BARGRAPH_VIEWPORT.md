# Bargraph: split-stage ↔ big screen

В `render_bargraph()` шкала находилась у правого края всего кадра. При big screen
VC показывает только crop `(59,27,210,153)` внутри `328×180`; прежняя шкала
оказывалась за его пределами. Это та область, которую отмечает рамка preview.

Теперь renderer получает видимую область отдельной командой и размещает все
16 сегментов внутри неё с отступом. Высота, ширина и промежутки масштабируются
вместе. Пиксели определяются в исходном кадре `328×181`; последняя строка ECC
исключается. Retina/SSAA не меняют пропорции.

При смене области положение и размер плавно меняются за **250 мс**, с плавным
началом и окончанием. Повторная смена цели продолжает движение из текущего
положения; повтор той же команды не перезапускает анимацию. Уровень, мигание,
сам манёвр и его текущий переход не сбрасываются.

**Правая сторона — основная.** Перенос влево допускается только при пересечении
выходного наконечника со шкалой. Сторона определяется **при смене манёвра** по
конечной геометрии входящего манёвра, до запуска перехода. Во время движения
стрелки и камеры она зафиксирована. Таймеров 100/400 мс и покадрового выбора нет.
Сама смена стороны происходит **за один кадр**, без затухания и без двух шкал
одновременно. Плавность 250 мс применяется только к положению/размеру внутри
меняющейся области big/small; сторона для неё выбирается сразу по конечному crop.
Ствол стрелки, кольцо кругового движения, круглый bulb и серые дороги
не вызывают перенос. Если оба края заняты наконечником, выбирается меньшее
пересечение, при равенстве — справа. Гарантии отсутствия пересечений во всех
промежуточных положениях анимации нет: они намеренно не меняют выбранную сторону.

`maneuver_select_bargraph()` строит отдельный mesh конечного манёвра теми же
path/extrusion-функциями. Расчёт сохраняет параметры подъёма активного перехода.
В mesh отдельно отмечены вершины призмы наконечника. Проектируются именно они
через общую функцию камеры, с конечной перспективой и положением камеры.
Пересечение считается по треугольникам,
обрезанным прямоугольником шкалы с запасом 3 исходных пикселя для тени;
пересечения одного лишь bounding box недостаточно.

Новый манёвр в `pending` не влияет на текущий переход: сторона меняется только
при его продвижении в `next`. Прямое появление после CLEAR, NONE и обновление
геометрии текущего/входящего манёвра также обновляют выбор. Смена crop, перспективы
или пропорций framebuffer пересчитывает его по сохранённому конечному наконечнику.
Уровень и мигание шкалы не участвуют в выборе стороны.

Каждый сегмент получил лёгкую чёрную drop shadow для отделения от дороги
и стрелки: сдвиг примерно `(0.75,1)` исходного пикселя и растушёвка до 2 пикселей.
Тень масштабируется со шкалой, обрезается видимой областью и повторяет её
мигание/затухание. Цвета и порядок заполнения 16 сегментов сохранены.

## Передача области

`AltScreenModule` сообщает смену split/big stage → `RouteGuidance` будит свой
существующий worker → `BAPBridge.refreshRendererViewport()` читает crop через
`ClusterLayerController.maneuverViewport()` → `RendererServer` отправляет
`CMD_VISIBLE_AREA=0x08` → `render_set_visible_area()` меняет цель анимации.

Источник размеров — те же значения текущего OEM Layout, которые используются
для `dm.setCropping(98,...)`, без отдельного выбора внешнего вида renderer.
Обычные области: полный `(0,0,328,180)` и crop `(59,27,210,153)`. Если сам Layout
задаёт иную обрезку, отправляется именно она. Обновление Layout также будит worker.
Нового пакета iOS для этого не требуется.

Пакет по-прежнему 48 байт: `[0]=08`, `[1]=0`, `[2..9]` — четыре unsigned BE16
`x,y,width,height` в координатах исходного изображения с началом слева сверху.
Остальные байты нулевые. Повторная область подавляется только после успешной
постановки в очередь; reconnect сбрасывает кэш. Очередь хранит последнюю область,
сохраняет её при вытеснении обычных команд и не нарушает порядок CLEAR.
Backpressure повторяется worker через существующий интервал 500 мс.

Старые команды манёвра и bargraph не изменены. Для работы переключения stage
нужны новая Java-часть и новый renderer. До получения области native использует
crop big screen как безопасный вариант. Изменения на автомобиль не устанавливались.

## Проверка

- Java target 1.4, route-info/манёвры и новый `RendererViewportTest`: PASS.
- Реальный socket transport: отдельный пакет области, CLEAR и очередь: PASS.
- Native ASan/UBSan: границы шкалы, возврат вправо, пересечение с реальной призмой
  наконечника и игнорирование ствола/bulb/хвоста, точное пересечение диагональных
  треугольников, 120 положений камеры/slide с неизменной стороной, продвижение
  очереди манёвров, неизменность живого mesh до/после preview, 250-мс интерполяция
  области и прерывание перехода: PASS.
- 24 реальных OpenGL-снимка: 12 манёвров × 2 stage. По разнице кадров с bargraph
  и без него проверены видимость и отсутствие перекрытых синих пикселей: PASS.
- GIF содержит промежуточные положения big/small и мгновенную смену стороны:
  каждый кадр содержит ровно одну шкалу, последовательность сторон —
  справа → слева → справа, без колебаний. Это кадры native renderer.
- Отдельный GIF показывает две смены манёвра с анимацией стрелки: появившаяся
  шкала использует сторону нового манёвра, без последующих перестановок.
- ARM/QNX renderer: сборка и проверка ARM ELF / отсутствия emutls: PASS.
