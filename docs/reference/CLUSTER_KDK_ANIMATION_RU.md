Основной KDK в начальной конфигурации прошивки появляется за **200 мс без начальной задержки**. Внутренний прогресс линейный. Разные элементы оформления используют разные участки этого прогресса, поэтому композиция проходит три фазы.

## Что анимируется

Основной параметр — `t_KDK_status`: появление 0 → 1, исчезновение 1 → 0.

В Basic/Classic от него непосредственно зависят:

| Составляющая | Свойство | Изменение |
|---|---|---|
| `t_DTM_placeholder` | `LayerOpacity` | Прозрачность контента |
| `KDK_hole_decorator` | `BlendIntensity` | Интенсивность декоративного элемента |
| `KDK_hole_fix` | `BlendIntensity` | Интенсивность дополнительного элемента |
| `t_KDK_hole` | `BlendIntensity` | Интенсивность элемента отверстия/маски |

Слова «рамка», «подложка», «маска» поясняют предполагаемую роль узлов по их именам и композиции. `BlendIntensity` — параметр материала: 50% этого параметра не обязательно означает 50% яркости конечного пикселя.

Прямой привязки перемещения, вращения или масштаба к `t_KDK_status` в проверенных пакетах не найдено. Движение окружающих частей управляется другими параметрами.

## Длительность и кривая

В `ClusterFull → SpeedTube` поле `m_kdkFadeAnimation` привязано к `DPID 0x02000329`. Начальный массив в бинарнике:

```
[0, 20, 0, 20]
```

После умножения на 10 мс:

```
[0, 200, 0, 200] мс
```

Начальная задержка — 0 мс; появление и исчезновение по этому пути — 200 мс. Для обоих направлений данный участник использует первую пару параметров. Кривая внутреннего скалярного таймера линейная, без ease-in/ease-out, пружины, отскока и превышения конечного значения.

```
p = clamp(t / 200 мс, 0, 1)
```

За каждые 20 мс прогресс увеличивается на 10 процентных пунктов. Отсчёт ведётся от начала локальной анимации, а не от нажатия кнопки или прихода CAN-сообщения.

## Появление Basic/Classic по времени

### 0 мс: исходное состояние

Контент полностью прозрачен. Декор и `fix` имеют нулевую интенсивность. У `Hole` численно интенсивность равна 1, но при p = 0 отдельное условие `Visible` выключает узел.

### 0–80 мс: проявляется оформление

- Контент: 0 → 40% opacity.
- Декор: 0 → 100% интенсивности.
- Fix: 0%.
- Hole: 100% интенсивности, если разрешена видимость.

Декор проявляется в 2,5 раза быстрее основного прогресса.

### 80–120 мс: включается дополнительный элемент

- Контент: 40 → 60%.
- Декор: 100%.
- Fix: 0 → 100% за 40 мс.
- Hole: 100%.

### 120–200 мс: завершается раскрытие

- Контент: 60 → 100%.
- Декор и fix: 100%.
- Hole: 100 → 0%.

На 200 мс код закрепляет `t_KDK_status = 1`.

Таким образом, оформление проявляется раньше контента, в середине быстро подключается дополнительный элемент, а в последней фазе затухает элемент маски. Контент проявляется непрерывно все 200 мс.

## Формулы для воспроизведения

Для p в диапазоне 0–1:

```
Контент = p
Декор   = min(2.5 × p, 1)
Fix     = clamp(5 × p − 2, 0, 1)
Hole    = clamp(2.5 × (1 − p), 0, 1)
```

Коэффициенты упрощены из сериализованных float32. Если длительность равна D:

- Первая фаза: 0 … 0.4D.
- Вторая фаза: 0.4D … 0.6D.
- Третья фаза: 0.6D … D.

При D = 400 мс это 0–160, 160–240 и 240–400 мс.

## Исчезновение

Для полного локального перехода p = 1 → 0 за 200 мс:

- 0–80 мс: Hole 0 → 100%; контент 100 → 60%; декор и fix остаются 100%.
- 80–120 мс: fix 100 → 0%; контент 60 → 40%; декор и Hole остаются 100%.
- 120–200 мс: декор 100 → 0%; контент 40 → 0%; fix остаётся 0%, Hole — 100%.
- При p = 0 узел Hole выключается условием видимости.

Менеджер умеет разворачивать уже выполняющиеся анимации с сохранением непрерывности. Применимость этого механизма ко всем сочетаниям KDK-событий не установлена.

## Sport: отдельная стеклянная подложка

Параметр `gp_sd_KDK_state` имеет собственный линейный таймер HubContent:

| Переход полного диапазона | Длительность |
|---|---:|
| Появление | 300 мс |
| Исчезновение | 200 мс |
| Принудительное мгновенное переключение | 0 мс |

При появлении с нуля:

| Время от собственного запуска, мс | Значение |
|---:|---:|
| 0 | 0% |
| 50 | 16,7% |
| 100 | 33,3% |
| 150 | 50% |
| 200 | 66,7% |
| 250 | 83,3% |
| 300 | 100% |

При старте с промежуточного значения длительность пропорциональна оставшемуся расстоянию: с 40% до 100% — 180 мс при номинальных 300 мс.

Материал `centerTube_SD_KB_plate` дополнительно зависит от общей трансформации:

```
Интенсивность стекла = max(1 − 3 × t_morph, 0) × gp_sd_KDK_state
```

При t_morph = 0 стекло следует собственному таймеру; при t_morph = 0.1 максимальный множитель равен 0.7; при 0.2 — 0.4; при t_morph ≥ 1/3 вклад нулевой.

200 мс основного KDK и 300 мс стекла нельзя просто сложить. Точное взаимное смещение их запусков ещё не восстановлено. Также нельзя объявлять 300 мс общей длительностью всей композиции.

Контент Sport использует `t_follow_fade`, поэтому таблица прозрачности контента Basic/Classic не переносится на Sport целиком. Правила интенсивности и видимости Hole в Sport присутствуют.

## Одновременная смена компоновки

Влияют отдельные параметры `t_morph`, `t_hub_morph_Right`, `t_flapStatus_right`.

Вклад flap в проверенных Basic и Sport ресурсах для обычного диапазона 0–1:

```
5 × max(t_morph − 0.8, 0) × t_flapStatus_(left/right)
```

При общей трансформации он начинает проявляться только на последних 20% диапазона t_morph. Это формула интенсивности, не полная траектория геометрии flap.

Условие видимости Hole:

```
p × (step(1, t_morph) + step(t_morph, 0))
```

При 0 < t_morph < 1 узел выключен; на концах диапазона разрешён при p > 0. Привязка помечена delayed; её точная задержка относительно рендера не установлена. Поэтому таблица основного fade предполагает устойчивую компоновку.

## События и ветвления

| ID | Имя |
|---:|---|
| 14 | KDKFadeOut |
| 15 | KDKFadeIn |
| 16 | KDKHoleFadeOut |
| 17 | KDKHoleFadeIn |
| 18 | KDKFlapFadeOut |
| 19 | KDKFlapFadeIn |

Функция с именем openKDKHole в логах отправляет именно событие 15 двум целям. Это не доказательство двух последовательных переходов по 200 мс.

Для входящего основного fade проверяются KDK-visible, отсутствие hideKdk/follow и числовое состояние виджета > 14. Полный смысл всех числовых состояний не восстановлен.

В updateKDK различаются preview, follow и обычный режим. Preview очищает fade-параметры. Follow устанавливает KDK = 0, а follow/ETA/DTM = 1. Обычная видимая ветка включает ETA/DTM и отправляет KDKFlapFadeIn; невидимая очищает KDK/ETA/DTM и отправляет KDKFlapFadeOut. Эти ветвления мешают считать любой показ KDK одной и той же анимацией.

## Внешняя синхронизация и настройки

200 мс — подтверждённая начальная конфигурация бинарника. На реальной приборке возможны сохранённые переопределения.

Инженерное меню содержит `KDK Fade Duration (10ms)`, `persys 0x2 52`: диапазон 0–2000 мс, шаг 10 мс. Точная цепочка setter от меню до массива DP ещё не восстановлена. `poll 1000` — период опроса меню, не длительность анимации.

Менеджер может принимать внешний прогресс через DPID33555173[annotationId], при выполнении условий, включая DPID33555245 == 1. Один режим использует внешний прогресс непосредственно, другой использует его приход для запуска локального линейного таймера. Поэтому форма и длительность реального перехода могут зависеть от активного режима синхронизации.

Таймауты 5000/10000 мс внешнего прогресса — аварийные механизмы, не обычная длительность появления. Проверка восстановления KDK через 500 мс также не задаёт обычную длительность fade.
