**Исправления после сравнения с CatPlay, 2026-09-11**

Продолжение: [сравнение с Showcase / AirPlay2](SHOWCASE_AIRPLAY2_REVIEW.md),
включая дополнительные исправления OMX и новые сборочные артефакты.

Исходная база: mhi2-carplay `6fe1aa0`, локальный CatPlay `13d174e`.
Изменения относятся к хуку поверх штатного AirPlay 210.81. CatPlay используется
как дополнительный источник форматов и семантики; его закомментированные типы
потоков 103/111 не подтверждают работоспособность APAC или Audi altScreen.

Шесть ошибок из первого отчёта исправлены:

| Ошибка | Изменение | Проверка |
| --- | --- | --- |
| Полный TEARDOWN с отсутствующим/пустым streams сохранял наши потоки | Общая точка AirPlay нормализует такие запросы в NULL для всех модулей. Штатная функция получает исходный словарь. Трассирование использует ту же классификацию. | Настоящие audio interposers и дополнительный наблюдатель: NULL, отсутствующий streams, пустой массив, 103 и посторонний 100. |
| Ошибка отправки конфигурации позволяла открыть новый декодер на P-кадре | Сам forwarder требует сохранённую конфигурацию и IDR на каждом новом соединении, включая разрыв при config-only send и выключение/включение forwarding. | EPIPE на SPS/PPS, запрет P-кадра, затем config + IDR через реальное localhost-соединение. |
| Разные файлы смешивались внутри одной iAP2-сессии | Новый пассивный сборщик отслеживает file ID, session ID, Setup, first/last data, Cancel и размер файла. Не отправляет ACK или другие команды. | Перемежающиеся передачи, отдельный JPEG-значок приложения, отмена и несовпадение длины. |
| EXIF-миниатюра обрезала внешний JPEG | Конец изображения определяется последним пакетом файла, а не первым FF D9. | Синтетический JPEG 1330 байт со встроенной миниатюрой; проверка полного декодирования штатным stb в PNG 256×256. |
| Полный последний пакет ожидал следующего Recv | Достаточно полного текущего пакета с корректными длиной и контрольными суммами. | Все границы разбиения двухпакетного изображения; окончание буфера ровно на последнем пакете. |
| При нескольких изображениях в одном чтении терялось новое | Возвращается новейшее завершённое изображение; частичная следующая передача сохраняется. | Два полных изображения плюс начало третьего в одном Recv. |

При дальнейшем разборе исправлены дополнительные проблемы:

- Повторные пакеты больше не дублируют байты изображения. Сборщик проверяет
  обе контрольные суммы, упорядочивает пакеты и учитывает переход sequence
  через 255. Проверены испорченная контрольная сумма, повторная доставка и
  восстановление пропуска с уже полученным последующим пакетом.
- Более старая передача, закончившаяся после новой, не заменяет новую обложку.
  Порядок завершений также сохраняется между разбором Recv и постановкой в очередь.
- Сброс Identify удаляет ожидающую обложку и меняет поколение публикации.
  Уже выполняющееся декодирование проверяет поколение непосредственно перед
  записью PNG и уведомлением Java. Тест останавливает кодирование, выполняет
  сброс сессии и проверяет отсутствие старой записи/уведомления.
- Запись PNG обрабатывает EINTR и короткие записи до атомарной замены ссылки.
- Неблокирующий видеосокет после EAGAIN ждёт POLLOUT вместо загрузки процессора
  повторными send. Общий срок отправки ограничен и при частичном прогрессе/EINTR.
- Повреждённая длина NAL отклоняет весь access unit, вместо отправки правильного
  префикса повреждённого кадра.
- Неполная или слишком большая конфигурация avcC не публикует частичные SPS/PPS.
  Кэш конфигурации согласован с буфером парсера: 4096 байт вместо 512.
- Ошибки AES-CTR Init/Update завершают приём, а интервалы повторных запросов IDR
  измеряются монотонными часами. Переключатель forwarding защищён mutex.
- При отказе malloc во время замены sticky-кэша шины сохраняется предыдущая
  корректная запись и возвращается HOOK_ERR_MEMORY. Раньше has_last оставался
  выставленным при ненулевой длине и NULL payload: следующий replay мог упасть
  в memcpy. Проверено принудительным отказом второй аллокации на исходном и
  исправленном коде.
- Ошибка отправки синхронизации останавливает replay на первом сбое. Частично
  записанный пакет больше не дополняется заголовками следующих сообщений;
  неудачный начальный handshake не передаёт сокет потоку записи.
- Сокет шины проверяется по паре fd/поколение непосредственно перед записью.
  Закрытие и замена сериализованы с отправкой. При сбое shutdown будит recv,
  а close выполняет только connector после завершения чтения: номер fd не
  может перейти новому соединению или файлу, пока старое чтение ещё активно.
  Тест проверяет повторное использование того же номера fd и пробуждение recv.

Основные файлы: [airplay_seams.c](../../hook/framework/airplay_seams.c),

Сборщик обложек сохраняет ограничения действующего декодера: до 800000 байт на
файл. Одновременно буферизуются не более четырёх изображений; очередь пакетов
для восстановления порядка ограничена 1 МиБ, сырой буфер — 65535 байт.
При исчерпании очереди незавершённые передачи сбрасываются, чтобы не склеивать
данные через пропуск. Если Setup содержит тип, принимается только artwork 2.
Проверка на HU 2026-09-12 выявила также 8-байтовый Setup только с размером:
он поддерживается без обязательного поля типа (9-байтовый остаётся ошибкой).
Для отправителей с таким Setup или без Setup допускается JPEG/PNG с сигнатурой строго
в начале отдельной передачи, включая сигнатуру, разбитую между пакетами.
Согласованные через SYN идентификаторы сессий сохраняются при Identify.

Регрессии, выявленные при развёртывании, разобраны в
[отчёте проверки altScreen и обложек на HU](ALTSCREEN_COVERART_LIVE_REGRESSIONS.md).

Проверки:

- `sh scripts/run_tests.sh`: полный набор host-тестов, включая новые проверки
  сборщика, публикации обложки, видеопередатчика и шины. APAC-интеграция использует
  имеющийся приватный захват; файлы захвата и ключи не добавлены в Git.
- Audio interposers и четыре новых теста проверены с AddressSanitizer/UBSan.
- Clang Static Analyzer для coverart_stream.c, altscreen_av.c и bus.c — без замечаний.
- Сборка QNX ARMv7 через `scripts/build_hook.sh`; итоговый вариант `LOG=0`, без
  AUDIO_STATE_TRACE. Сохранены проверки экспортов, emutls, C++ runtime и ABI.
- Изображение в `tests/fixtures/coverart/` синтетическое, не из телефона.

На ГУ изменения не развёрнуты. Следующая проверка на автомобиле: обычное
подключение/отключение, быстрый replug, серия смен трека с обложками, переключение
режима карты и восстановление видеопотока после перезапуска рендерера. Host-тесты
подтверждают обработку байтов, ошибки I/O и порядок действий; они не проверяют
поведение QNX OMX, физического USB и дисплея кластера.
Для шины дополнительно проверить переподключение после перезапуска Java HMI и
возврат актуальных обложки/навигационных данных после повторной синхронизации.
