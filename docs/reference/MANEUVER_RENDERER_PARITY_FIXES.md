# Согласование CarPlay → BAP/HUD → maneuver_renderer

Исправления от 2026-09-11. Это текущий статус после первоначального
[аудита расхождений](MANEUVER_HUD_RENDERER_AUDIT.md) и
[проверки sentinel-значений в iOS](IOS_MANEUVER_ANGLE_SENTINELS.md).

**Исправлены ошибки передачи, missing-значений и конфликтующей стороны.** BAP
задаёт смысл и безопасный fallback, а renderer сохраняет более подробную геометрию.
По уточнению пользователя полные кольца для ENTER/EXIT_ROUNDABOUT возвращены;
допустимые углы TURN, согласованные со стороной манёвра, снова передаются точно.
OFF_RAMP и ON_RAMP используют одну пологую стрелку в обоих изображениях.
Renderer получает исходные дороги и углы номерных съездов с круга.
Рисунок остаётся процедурным: толщина, цвет, перспектива и анимация отличаются от HUD.

Первоначальное сведение renderer к дискретным иконкам BAP было чрезмерным:
различие рисунка само по себе не является ошибкой. Для обычного TURN у HUD есть
готовые варианты 0°, ±45°, ±90°, ±135° (s26…s32); отдельного варианта на 160° нет.
Наш renderer способен строить 160°, поэтому у него это ограничение снято.
Подъём при самопересечении (|угол|>150°) снова достижим для таких TURN.
[Реальные кадры восстановленных колец и sharp ±157°](../../output/maneuver-parity/restored-geometry.png).

Наличие ресурса короткого выхода s112/s113 в прошивке не доказывает, что iOS
присылает MT_EXIT_ROUNDABOUT=7 в реальной поездке. В BAP выбор для MT6/7 в ходе
этих изменений не менялся; отменена именно подгонка renderer под эти ресурсы.

[Один лист всех 54 типов, HUD рядом с renderer, RHT/LHT](../../output/maneuver-parity/hud-renderer-54.png).
Слева собраны оригинальные слои HUD, включая дороги, справа — реальные кадры
OpenGL. Для каждого типа указан конкретный входной угол. EXIT_1…EXIT_19 показаны
при одинаковых +90°: номер съезда не определяет направление выхода.

сегмента: прямо → по диагонали → снова прямо. Теперь HUD и renderer показывают

дороги; по числу и углам они могут быть подробнее HUD.

## Углы и защитные значения

В iOS 27 проверенный сериализатор передаёт signed16 без специальной обработки
±1000. Отсутствующее NSNumber приводит к отсутствию TLV. **+1000 создаёт наш
C-парсер для отсутствующего exit angle; −1000 сохраняется как защитный случай.**
Ноль — настоящий прямой угол. Внутри slot State значение −1 остаётся initial
value для совместимости, но новый boolean отличает его от принятого −1°.

Четырёхаргументный `ManeuverMapper.map()` сохраняет legacy-контракт «−1 отсутствует».
Реальный bridge использует overload с наличием поля. Поэтому:

- U-turn / LHT / полученный −1° → левая петля;
- тот же U-turn без поля → правая петля по стороне движения;
- generic манёвр с ±1000 → прежний straight fallback, без трактовки знака sentinel;
- ±1000 перед roundabout-квантизацией не превращаются в ±180°;
- реальные значения вне ±180 сохраняют прежние fallback-правила mapper.

У `turn_angle` и `exit_angle` один источник: iAP2 JunctionElementExitAngle.
Если пришли оба ключа с разными значениями, явный `exit_angle` побеждает.
Malformed numeric angle получает +1000.

## Протокол и обновления

Размер TCP-команды остался 48 байт. Новый флаг `MAN_FLAG_BAP_GEOMETRY=0x04`
обозначает signed half-degrees: например −135 на проводе означает −67,5°.
Нативное состояние хранит float-градусы; передаются как точные 16 BAP-направлений, так и исходные целые градусы renderer.
`MAN_FLAG_SNAP_TO_ROAD=0x10` отдельно разрешает совмещение на круге, сохраняя
единицы half-degrees. Он выставляется только для MT6/7/28…46 с допустимым
исходным углом. В packet входят исходные дороги, включая активный выезд;
совмещение поверх BAP roads, где этот выезд удалён, не используется. Изменение
разрешения snap входит в кэш геометрии и не теряется при одинаковом числовом угле.
Старые команды без флага 0x04 по-прежнему используют целые градусы и legacy snap.

`MAN_FLAG_REFRESH=0x08` используется только при изменении дорог того же
слота/версии, без изменения основного манёвра. Нативный engine заменяет актуальный
current/next/pending и сохраняет текущую анимацию. При объединении нескольких
пакетов новый манёвр не теряет transition из-за последующего refresh.
Версия или слот поменялись — обычный новый переход. Повторный ARRIVED с той же
геометрией по-прежнему не перезапускает анимацию флага.

NONE очищает геометрию напрямую и не строит промежуточный путь ARRIVED.
Deferred perspective/bargraph применяются и при таком переходе в IDLE.
Расчёт дистанции, пороги и режимы bargraph не менялись.

**Для установки нужны новая Java-часть и новый `maneuver_render` вместе.**
Новый бинарник принимает старые команды, но старый бинарник не понимает флаг
half-degrees и новые ICON 8/9. На автомобиль эти изменения не устанавливались.

## Границы совпадения

Это согласование используемых команд, а не попиксельная копия HUD. В частности,
Полные кольца renderer для MT6/7 сохранены намеренно. Короткая дуга ICON9 остаётся
доступна как отдельная нативная команда, но CarPlay bridge её больше не выбирает.
Точные контуры, пропорции, оптика и анимация оригинальных ресурсов не перенесены.

FOLLOW_STREET имеет отдельный путь в HUD: пустой selector первого 3D-слота не
означает пустой HUD. Renderer сохраняет APPROACH. Эмуляция здесь фиксирует активный
3D mode 3, а не воспроизводит все переключения режимов панели.

BAP zLevel по-прежнему передаётся HUD, но renderer не изображает отдельный z-marker.
В проверенном CarPlay-потоке нет источника такого поля; собственный подъём стрелки
renderer — визуальный эффект. Отдельное обозначение номера съезда также не
добавлялось: текущий BAP descriptor его не несёт. Неиспользуемые CarPlay типами
семейства BAP не назначались без данных, которые объясняли бы такой выбор.

Финальная проверка на машине нужна для реального времени обновлений, оптической
проекции, режимов панели и переходов. Offline-проверки этого не заменяют.

## Решение после повторной оценки

Рекомендации 1 и 2 реализованы: точные углы номерных съездов с круга, аккуратное
совмещение и исходные боковые дороги renderer восстановлены. Рекомендация 3
вернуть MERGE отклонена пользователем: форма рамп должна быть похожей на HUD,
без стрелки из трёх сегментов. В соответствии с этим уточнён также выбор OFF_RAMP.
Полные круги, точные совместимые sharp-повороты и прежний подъём при наложении
сохранены. Код отдельной короткой дуги ICON9 остаётся доступным на уровне native
protocol, но bridge его не выбирает.

Остальные исправления сохранены: sentinel/presence/aliases, конфликтующая сторона,
первичный слот, сравнение дорог/версий, retry после отказа enqueue, roads-only
refresh, NONE, направление generic TURN, явный U-turn на круге и CHANGE_LANE.
Это не заключение обо всём репозитории.
