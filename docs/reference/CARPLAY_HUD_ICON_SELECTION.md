# Выбор HUD-иконок для всех типов CarPlay

> Исторический снимок до согласования renderer. Выбор съездов 8/22/23 ниже заменён: теперь TURN slight s27/s32, без третьего сегмента; −1° на реальном входе отделён от отсутствующего поля. Текущие исправления, проверки и новый лист 54 типов: [MANEUVER_RENDERER_PARITY_FIXES.md](MANEUVER_RENDERER_PARITY_FIXES.md).

**Проверены все 54 типа: для 8 уточнено направление, 46 сохранены.** Изменения внесены в ManeuverMapper. Это выбор BAP-иконки, не полная переделка геометрии нашего OpenGL renderer.

[Единый лист выбранных иконок, RHT/LHT](../../output/maneuver-selection/carplay-hud-selected-54.png). [Каталог всех доступных s000–s120](../../output/maneuver-audit/hud-all-maneuvers.png).

Основание выбора: сначала смысл ManeuverType, затем действительно доступный угол одного узла. Число сегментов дороги, параллельные дороги, развилка и сложный двойной поворот не выводятся только из знака угла. Сохраняется прежний junctionType gate; конфликтующий или неподдерживаемый тип узла не обходится ради картинки.

На листе 108 отдельных прогонов настоящего bridge: каждый тип в RHT/LHT, z=0, junctionAngles=[−90,0,+90]. Углы выбраны для демонстрации; это не запись дорожного движения. Исходный mapper для сравнения примеров скомпилирован из 28327b6 с проверкой SHA256 и загружен только в отдельном host-процессе.

## Изменения

- **8/22/23, съезды:** main 15/16, direction 00 → s033/s036. У общего OFF_RAMP угол определяет только сторону; у 22/23 сторона задана типом. sideStreets=[00] сохранены. s034/035/037/038 больше не выбираются, неподдерживаемые EXIT/A0 и EXIT/60 тоже исключены.
- **11/16/51, общий выход на дорогу:** сохраняется TURN, направление выбирается по 7 допустимым направлениям. Границы абсолютного угла: 0…22° прямо, 23…67° slight, 68…112° normal, 113…180° sharp. ±1000 и −1 → прежний fallback прямо; для прочих значений вне ±180° сохранён прежний выбор left/right по знаку. В TURN нет direction=80; разворот задаётся отдельным типом.
- **20/21, поворот в конце дороги:** сохраняются рассчитанные slight/normal/sharp. Противоречащий стороне угол и missing → обычный поворот в сторону типа. −1 обрабатывается как unset.

Для простого TURN угол описывает единственный поворот. Для EXIT те же числовые направления выбирают другое семейство геометрии, поэтому правило резкости обычного поворота к рампе не переносится.

## Решение по каждому типу

## Какие альтернативы не выбраны

- SERVICE_ROAD s039/s040 не подставляется вместо ON_RAMP: отдельная параллельная дорога не следует из одного типа въезда.
- FORK_2/FORK_3 s041…s045 не подставляются вместо KEEP: тип не гарантирует конкретную развилку. TURN + sideStreets остаётся общим представлением.
- SQUARE s078…s109 не подставляется вместо круга: в нашей цепочке нет признака прямоугольной площади.
- MICHIGAN/DOUBLE_TURN s116…s119 не строятся из одного exitAngle. Последующие maneuver slots сами по себе не задают геометрию такого сложного знака.
- PREPARE_U_TURN s114/s115 не заменяет U_TURN_WHEN_POSSIBLE: «при возможности» не равнозначно фазе предварительного показа.
- FOLLOW остаётся для NO_TURN/FOLLOW/FERRY без направления. Особая обработка 11/00/z0/empty не позволяет оценивать весь HUD только по s0.

## Проверка и ограничения

- Реальный Java bridge: 7,890 входов и отдельно 216 ramp-входов. Изменились 430 строк только у указанных 8 типов.
- Все 173 текущих уникальных дескриптора и отдельные примеры карточек покрыты исполнением V850 G1952/M2325: предыдущая матрица и 15 дополнительных сочетаний. Результаты двух прошивок одинаковы.
- Новых пустых 3D-моделей нет; восстановлены 32 строк матрицы с ранее неподдерживаемыми острыми EXIT.
- RendererMapperDirectionTest проверяет границы углов, missing, явную сторону и типы рамп. Production Java собрана с target 1.4.
- Команды нашего renderer не изменены. Известные различия MERGE против TURN, кругов, серых дорог и обновления кэша остаются отдельной задачей 1:1.
- Проверен выбор в активном 3D-режиме, а не переключение всех режимов/оптика HUD или фактический кадр штатной приборки. Автомобиль не обновлялся.
