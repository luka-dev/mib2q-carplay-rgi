# APAC 5.1 live corpus — 2026-08-31

## Назначение

Это несекретный manifest живой wired-CarPlay записи Audi MHI2Q MU1316. Сам corpus хранится только
локально в `captures/apac_5_1_live_20260831_0205`; каталог исключён из git, потому что SETUP содержит
32-байтный `shk` session key открытым текстом, а APAP stream содержит записанный программный звук.

## Состав локального corpus

- `spatial_apap_5.bin` — точная raw TCP-запись аудиопотока с HU;
- `spatial_setup103_5_request.bplist` — matching type-103 descriptor и `shk`;
- `spatial_magiccookie_5_60100d08f9d19abb.bin` — matching 33-byte `dapa` cookie;
- SETUP response и plists команд SETRATE, SETRATEANCHORTIME и FLUSHBUFFERED;
- локальные `README.md` и `SHA256SUMS` для проверки всех исходных artifacts.

## Финальный неполный record

Полная teardown остановила запись сразу после следующего четырёхбайтного inclusive-BE32 length
prefix. Поэтому parser справедливо сообщает, что после offset финального префикса осталось только
четыре байта. Это не повреждение предыдущего аудио: первые 1,320,015 bytes содержат 3980 полных
кадров, и все они проходят ChaCha20-Poly1305 authentication.

Raw evidence нельзя исправлять или обрезать. Для offline decoder work следует делать временную
копию первых 1,320,015 bytes и извлекать key из локального SETUP. Текущий
`tools/pioneer_apap_decrypt.py` затем подтверждает:

```text
frames=3980 verified=3980 failed=0 plaintext_bytes=1148875 modes=[extension12=3980]
```

Следующий этап: создать из verified plaintext отдельные APAC golden vectors и сравнивать новый
ARMv7/QNX decoder с `tools/apple_apac_oracle.c` до подключения PCM к DIO5.
