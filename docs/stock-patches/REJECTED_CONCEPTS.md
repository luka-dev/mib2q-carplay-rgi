# Отклонённые концепции и ошибки промежуточных версий

Сохранены механизмы и причины решений. Исполняемые реализации исключённых экспериментов и датированные дубли документов удалены. Это не очередь будущих задач: SDIO и PF QoS исключены по решению владельца.

## 📶 Промежуточные Wi-Fi-кандидаты

| Вариант | Наблюдение | Решение |
| --- | --- | --- |
| Три локальные RX-правки `ca529b2b` | Reorder expiry, window и timer hardening | Эти исправления сохранены внутри full; отдельная установка старого варианта не нужна |
| Full `ff67efd8` | Реальный ABBA: native `ra_list` → `wl_lock`, callback `wl_lock` → native `ra_list`; уход клиента с AP мог повесить весь io-pkt | Не использовать; gate/request переведены на trylock |
| `189a6315` | Trylock устранил ожидание чужого lock; исчерпание cookies теряло быстрые пробуждения | Не использовать; обычный TX продолжался через штатный callout |
| `662c24da` | Native fallback сохранял TX, но managed gate мог дать callback/аллокацию на каждую completion | Не использовать; финальная деградация возвращает также штатный gate |
| Fairness/WMM `f1e54d8b` | Модель ожидала асинхронный IRQ, реальный card worker работал синхронно; выгода на железе не показана | Исключён |
| Агрессивное снижение reorder timeout | Меньше ожидание, но при перестановках можно чаще терять полезные кадры; моделируемое время не равно RF | Не выбран как универсальный регулятор |

Captured timer UAF встречался также в stock; нельзя выдавать его за новую регрессию или утверждать, что все риски stock устранены. Косвенные ops-вызовы mlan ограничивают полноту статического обхода lock-графа.

## 🔌 io-sdiorm-mib2-qc

SDIO — транспорт между SoC и Wi-Fi/BT-чипом: обслуживание запросов/прерываний, чтение/запись карты и доставка событий. Он не определяет частоту кадров iPhone. Патч коалесцировал повторные уведомления функции Wi-Fi при сохранении lifecycle/read/write границ; Bluetooth function 2 оставлялась штатной. Одной проверки чтения 64 байт по адресу 0 было недостаточно для доказательства безопасности: остаются другие длины, ошибки и загрузка firmware.

| Вариант | Результат |
| --- | --- |
| Stock `ec30174b`, 65256 байт | Выбран |
| Патч `57e7464c`, 71744 байта | QEMU принимал ELF, но настоящий ГУ выдавал ENOEXEC до main: PT_INTERP перенесён в новый RX-сегмент |
| Исправленный `ee6ddf52`, 71744 байта | Перенос PT_INTERP в padding исходного RX позволил запуск; это подтвердило причину отказа загрузчика |
| Рабочий патч в нагрузке | Счётчик suppressed = 0: экономия событий не продемонстрирована; следующие тесты со stock дали заметно лучшие throughput/RTT |

В последовательном сравнении A → B были перезагрузка и изменения условий. Результат обосновывает выбор stock, но не доказывает точную причину замедления в патче. Повтор A2 отменён владельцем; это не незавершённое обязательство. [Таблица измерений](PERFORMANCE.md) сохраняет величину различия.

На проверенном ГУ executable находится в `/mnt/app/armle/sbin/io-sdiorm-mib2-qc`; раннее утверждение «только в IFS, заменить на /mnt/app нельзя» было неверным. Путь надо определять по `/proc/PID/exefile`. Наличие stock-копии не означает, что кандидат активен в памяти.

## 🌐 io-pkt, PF и приоритеты

`io-pkt-v6-hc` оставлен штатным. Использование его native callback/callout API Wi-Fi-патчем не является патчем io-pkt. Изучались callback ordering, очереди и PF/HFSC; выбранного нового бинарника io-pkt нет.

PF-концепция: CarPlay/control/ACK отдельным классом, фон второго клиента ограничить HFSC, обновлять адрес при активной сессии из receiver. Генераторы и дерево очередей проходили локальные проверки, но польза на железе не установлена. Решением владельца концепция отменена; обязательные порты сохранены.

Повышение thread priority и расширение socket buffers также не приняты как общий фикс. Больший буфер способен увеличить очередь и задержку; высокий приоритет одного worker может ухудшить обслуживание остальных. Приоритет временного измерительного receiver не является production-патчем.

## 🧪 Почему «меньше callbacks» не равно «быстрее»

В одном модельном тесте 128 completions дали stock 10168 инструкций / 8 callbacks, patched 37283 / 4. Дополнительная политика расходует CPU даже при сокращении callbacks. Для SDIO обычный путь вырос примерно со 119 до 349 модельных инструкций. Это свойства конкретного harness, не замер ARM CPU или полезного throughput. QEMU не эмулирует реальную радиосреду и не заменяет нагрузочный тест машины.
