# Результаты измерений и границы выводов

## 📶 Сравнение SDIO при одинаковом полном Wi-Fi

Последовательные тесты ГУ 2026-10-23: Wi-Fi `47a370bc`, канал 1, два прогона каждой фазы; экспериментального PF QoS нет. A — SDIO-патч, B — настоящий stock SDIO после перезагрузки. Полностью штатный Wi-Fi здесь не использовался.

| Метрика | A: SDIO patched | B: SDIO stock, выбран |
| --- | --- | --- |
| TCP Mac → ГУ, Мбит/с | 27,1–31,1 | 44,7–46,6 |
| TCP ГУ → Mac, Мбит/с | 23,4–26,0 | 34,9–35,6 |
| UDP target 30, received Мбит/с | 28,9 / 29,3 | 29,5 / 29,4 |
| UDP target 30, потери | 28 / 157376 | 0 / 159332 |
| Ping p95 при UDP30, мс | 62,277 / 98,624 | 17,864 / 20,384 |
| UDP target 45, received Мбит/с | 38,5 / 41,6 | 43,8 / 43,8 |
| UDP target 45, потери | 81 / 145317 | 0 / 158547 |
| Ping p95 при UDP45, мс | 137,748 / 185,383 | 37,156 / 32,128 |
| Ping p95 idle, мс | 51,028 / 49,728 | 8,735 / 7,036 |

В A отправитель реально предлагал около 39,2/42,2 Мбит/с вместо 45 и получил 4049/1799 локальных ENOBUFS. В B реально предложено около 44,4 Мбит/с, ENOBUFS = 0. При B суммарно **0 потерь из 317879 UDP-пакетов**, но максимальный RTT одной UDP45-фазы достиг 130,874 мс: p95 не является максимумом.

PID SDIO и io-pkt в B оставались неизменными между фазами; BT был жив, AP активен, четыре PF-профиля не менялись. После теста временные receiver/listener были убраны. Эти проверки не заменяют долгий тест в движении с конкурирующими клиентами.

## 🧪 Причинность и CPU

Перезагрузка, фон и радиосреда не были полностью уравнены; A2 не выполнялся по решению владельца. Поэтому корректный вывод — выбранная конфигурация показала лучший практический результат в этих прогонах, а не доказанная причинная прибавка от одного изменения. У SDIO-патча подавленных событий было 0; механизм его предполагаемой регрессии не установлен.

В B CPU SDIO при UDP45 был 32,8–34,4%, io-pkt 37,8–40,2%; idle примерно 1,2% и 3,0%. Это **проценты одного ядра**, четырёхъядерный суммарный предел 400%. CPU не оказался равномерно ниже A, поэтому заявлять общее снижение CPU нельзя.

Сохранённая ранее нагрузка CarPlay включала AltScreen с целевой частотой 30 FPS in motion, main screen in motion и 5.1 playback: DIO 39,4%, AltScreen 11,4%, Maneuver 8,5%, MCD 10,0%, видеокодировщик 13,7% в той же шкале одного ядра. Это исторический снимок из обсуждения; для него здесь нет сопоставимого stock-контроля или новых сырых измерений. Его нельзя использовать как доказательство процента ускорения от текущего пакета.

## 📚 Предыдущий пик и источники

На 2026-10-22 с stock SDIO и старым Wi-Fi `ff67efd8` получено TCP 45,7–46,1 Мбит/с и UDP 43,5–44,0 без потерь (0/250398). Этот драйвер позже отвергнут из-за ABBA-deadlock. Пик около 45 Мбит/с достижим и раньше; выбирать небезопасную старую сборку ради него нельзя.

[Сводка свидетельств](evidence/measurements.json) содержит исходные пути, SHA локальных отчётов и фактические значения. Полные локальные captures в игнорируемом `build/` не нужны для чтения этой таблицы; сводка хранится с документацией. Модели и QNX-пробы проверяют функциональную корректность, а не физическую максимальную скорость.
