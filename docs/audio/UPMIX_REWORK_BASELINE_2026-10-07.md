# UPMIX rework baseline (2026-10-07)

*The understanding the rear-scene redesign rests on: what runs in the car, why the rear is faint and unstable, every line of work since 2026-09-04 with its outcome, the established positives and negatives, the hard constraints, the metrics and their blind spots. Built 2026-10-07 from a full re-read of docs/audio, the memory notes, the hook runtime, the model code and the git history. Not a design.*

---

Synthesis of 20 cluster reports (memory notes, docs/audio, hook C runtime, model code, git history to 2026-10-04) for the owner's redesign of the MHI2 CarPlay stereo-to-5.1 upmix. Goal of the redesign: strong, stable rear scene, front intact. This document is the understanding, not the design.

Evidence tags used throughout: **[car]** heard by the owner in the vehicle (sighted, one listener unless stated); **[log]** measured on the unit (bench, hook log); **[offline]** real music (MoisesDB stems / owner library) through the real C renderer on a PC, nobody listened; **[synth]** synthetic scenes; **[frag]** one or four short training crops; **[oracle]** uses true stems or future data, cannot ship; **[model]** static J525 reverse-engineering, electrical not acoustic; **[inferred]** stated in a doc without a measurement.

Platform naming: all docs say the MMX is an APQ8064/Krait at 1512 MHz under QNX 6.5. "Tegra3" in the memory index belongs to the MU1439 port, not this unit.

## 1. The system as it runs in the car today

State = best install build `build/install_protected_WAUZZZF47HA098927.zip` (SHA-256 710342a1…075f, 2026-09-28, from 800de9d / Track A final 04fb06d). Nothing under `hook/audio/{stereo_upmix,hssr_*}`, `models/` or `carplay_startup.sh` changed after 2026-09-27 (git). Owner blind listening of this build: pending.

### 1.1 Phone to hook

- Two CarPlay audio streams, both upmixed by the same renderer code with separate DSP state:
  - **type-100 realtime** (Spotify and every non-103 app): always `lpcm` 48 kHz/16-bit/stereo on `mpl5_dio_ent`; iOS refused PCM 5.1 (bit 44) and AAC-ELD 5.1.2 (bit 42) live [car]. Upmixed inside stock's QSA write thread (`AUDIO_REALTIME_UPMIX=on`, 21.09), period 768 frames = 16 ms, only while every tracked main object is media (no phone/Siri/alert) and the route is not faulted; otherwise plain L/R, zero rears, silently.
  - **type-103 buffered** (hook-owned receiver): AAC-LC idx 23 (Cinemo) or APAC idx 65 (= discrete 5.1, `libcarplay_apac.so`, 2.9–3.7 % of a 21.3 ms packet budget in QEMU). Decoder chosen by the inline magic cookie, not the SETUP index. **Discrete APAC 5.1 bypasses the upmixer** (reorder `{1,2,0,5,3,4}`); 5.1.2 (idx 66) never advertised (`AUDIO_SPATIAL_ATMOS=0`).
- SoundCheck programme gain (AAC −9 dB, APAC +1 dB, 20 ms ramp) is applied **after** the upmix, limiter off, because the model features are absolute log-energy (LANDMINES 202 and the design note say after the cabin guard; DISCRETE_5_1_ROUTING says before trim/reorder/upmix, host-verified only — the docs conflict). Headroom of +1 dB after the guard: never captured.
- Output rail: fixed PCM6 48 kHz S16 in Apple/deva order L R C LFE Ls Rs for the whole session, ASAD 0xfc; C is always digital 0 ("the J525 derives its centre").

### 1.2 Hook framing, threads, resets

- `libcarplay_hook.so` LD_PRELOADed into `dio_manager`; `stereo_upmix.c` (time-domain chain) + `hssr_dsp.c` (STFT) + `hssr_neon.c` (GRU) + `hssr_mask.c` (mask net) + `hssr_control_worker.c`.
- Blocks ≤ 1024 frames (buffered path 21.333 ms) / 768 frames (realtime). Audio thread: STFT, masking, synthesis, post chain; never allocates/locks/logs.
- One control worker per instance (SCHED_RR 17 requested, result discarded = unproven; buffered thread 18). Two-slot lock-free job/result mailboxes; results applied **one control (10.67 ms) later**; 2 jobs outstanding = busy++, result discarded if generation mismatches or sequence too new.
- Realtime deadline guard (`rt_upmix_guard.h`): budget 12 ms of the 16 ms period, 4 consecutive overruns disable the upmix (rears go silent), 64 cold periods (~1 s) excused after every arm/reset, revival only after a ≥ 500 ms stream gap (never mid-track, by design).
- `spa_stereo_upmix_reset()` on every stream start, rate ≠ 1, flush with prefix reset, new decoder cookie, stock prepare, or any non-upmixed realtime period: memsets the whole runtime (slots, masks, bed ring, limiter, makeup = 1.0, GRU/mask state). Every track starts cold: 512 frames of silent rear, then ~0.3–1 s of rising band masks. Until c43a17c (27.09 evening) this memset also dropped the guard and mask pointers, so **the mask net had never run in the car before 2026-09-27 evening** and the guard died on the sync path [log: maskReady=0].

### 1.3 Analysis geometry

- STFT 512 / hop 128 at 48 kHz (2.667 ms hop), 257 bins, sine window, 4× overlap, synthesis window = analysis / Σw² with 1/N folded; one packed Hermitian inverse FFT yields both rear channels, a second one the source image. Algorithmic latency 512 frames = 10.667 ms; fronts delayed exactly that (bit-exact S16 delay line, not STFT output).
- 32 bands, edges (Hz): 0, 60, 90, 125, 170, 220, 280, 350, 440, 550, 680, 830, 1000, 1200, 1450, 1750, 2100, 2500, 3000, 3600, 4300, 5100, 6000, 7000, 8200, 9600, 11200, 13000, 15000, 17500, 20000, 22000, 24001. At 93.75 Hz bin spacing the bands 60–90, 125–170, 220–280 Hz contain no bin.
- A "control" = every 4th hop = 512 samples = 10.667 ms (93.75 Hz). Per hop: per-bin PL, PR, cross-spectrum, mid/side, flux; per band spatiality = smoothstep(|pan|, 0.035, 0.50), diffuse = 1 − coherence.

### 1.5 Per-band routing (q6d + guard, `spa_hssr_update_controls`)

- Softmax; if p_vocal < 0.4 → ×2.5 else 1.0 (q6d reads processed leads as low as 0.19). target = smoothstep(sigmoid(rear logit), 0.12, 0.36).
- vocal_risk = p_vocal·(1 − 0.8·spatiality), max with guard_vocal.
- target ×= (1 − 0.92·vocal_risk)⁴ × (1 − 0.85·p_bass)⁵ × (1 − 0.35·p_drums) × (1 − 0.10·p_guitar) × (1 + 0.85·(p_strings + p_keys)) × (0.72 + 0.28·focus) × (0.70 + 0.30·global_safety) × **16** (makeup).
- **Hard band limits**: 0 for bands with upper edge ≤ 220 Hz; linear ramp 220→350 Hz; ×0.65 from 15 kHz; ×0.25 from 20 kHz. On top of that the training-time `OBJECT_FOCUS_PRESENCE` curve is 0.05 at 220–280 Hz, 0.10 at 280–350, then 0.20 / 0.35 / 0.50 / 0.70 / 0.85 up to 1 kHz, 1.0 only from 1 to 9.6 kHz, tapering to 0 above 22 kHz — the 350 Hz–1 kHz body cut is far larger than the ramp alone suggests [code].
- band_mask EMA 0.35 up / 0.035 down per control (~0.3 s release); band_pan EMA 0.28 of tanh(pan) bounded ±0.85; band_vocal_veto = smoothstep(p_vocal, 0.5, 0.9) EMA 0.35 / 0.03 (~0.35 s); vocal_presence = smoothstep(mean veto of the 350–2500 Hz bands, 0.30, 0.60) EMA 0.10 / 0.02; focus_rescue (dense electronic masters misread as drums) EMA 0.40 / 0.025; universal_safety EMA 0.45 down / 0.12 up.

### 1.6 Per-bin object

- **Heuristic path** (runs always; drives the beds; drives the object only when the mask is not ready): 4 slots (0/2 left, 1/3 right), candidate = semantic × smoothstep(directed pan, 0.025, 0.40) × (0.55 + 0.45·coherence) × transient support, no bands ≤ 220 Hz; slot confidence EMA 0.26 up / **0.006 down**, hold 94 hops = 250 ms, band_weight EMA 0.34 / **0.010** (~1 s), slot pan EMA 0.020 (confident) / 0.055; per bin best_score = max slot band_weight × pan match (0.12..0.52), ridge gate smoothstep(mag/band avg, 0.70, 1.65), coherence weight 0.5 + 0.5·smoothstep(coh(45 ms EMA), 0.25, 0.55), bin mask EMA 0.50 / **0.020** (~0.13 s), object_pan EMA 0.18 toward the slot.
- **Mask path (shipped)**: mask = sqrt(e^γ)·drive_bin with γ = 1.0, drive = 1.5 flat (treble shelf off), object_pan = scene_lr (bin's own smoothed L/R balance, EMA 0.05/hop ≈ 53 ms). Slots/ridge/coherence bypassed for the object amplitude.
- **Vocal gate** (25.09, shipped 0.5): final mask ×= 1 − 0.5·vocal_presence·band_vocal_veto·g, g = smoothstep(como, 0, 0.40) EMA 0.05, como = per-bin running correlation (EMA 0.012/hop ≈ 0.22 s) of the bin's log energy with the voice-body log energy (veto-weighted 350–2500 Hz).
- mask bounded 0..1.45; pan ±0.95; source vector (1+pan, 1−pan) normalised; steering vector hard-focused to ±(0.78 + 0.17·smoothstep(|pan|, 0.05, 0.92)); rank-one projection proj = 0.5·(sl·L + sr·R). **Rear object = mask·steer·proj** (coherent, no decorrelation). **Source image for front subtraction = min(mask,1)·band_front_keep·source·proj**, band_front_keep = 1 because BED_ATTACK is off.

### 1.7 Beds (what makes the rear "not dead")

- Ambience: ±ambience·side, target 0.018·band_mask·diffuse·(1 − best) bounded 0..**0.04**, EMA 0.10 / 0.015.
- Universal ("no-dead-rear"): object_absence·presence·content_floor·ridge·motion bounded 0..**0.55**, or diffuse layer 0.35·universal_safety·(1 − smoothstep(coh, 0.25, 0.60))·(1 − best) if larger, EMA 0.28 / 0.012; rendered as mid rotated by a fixed per-bin conjugate phase (18 + (bin·13) % 47), pan 0.72·clamp(3·scene_lr); zero below 220 Hz; scaled by universal_makeup = AGC toward 32 % rear power, **bounded 1.0..1.5**.
- **Rear air bed** (`AUDIO_STEREO_REAR_AIR_DB=−9`, linear 0.355): band_air·L and band_air·R copied straight into the bed, band_air = 0.355·smoothstep(band low edge, 2 kHz, 4 kHz); constant gain, no decision, never subtracted from the front. The only static rear component.
- Bed delays (`AUDIO_HSSR_BED_DELAYS=on`): bed = 0.79·now + 0.60·delayed_same_side − 0.14·delayed_other_side (unit energy for uncorrelated copies), per band group (0–220 / 220–680 / 680–1450 / 1450–3000 / 3 k+ Hz): Ls 12/9/4/2/1 hops (32/24/10.7/5.3/2.7 ms), Rs 15/7/6/3/2 hops (40/18.7/16/8/5.3 ms); ring 16 hops. Cuts Ls/Rs coherence 2–8 kHz 0.50 → 0.40 [offline]. Dolby 64-sample unit for these delays is a hypothesis (if 1024, they would be 64–660 ms).
- Bed attack detector (`AUDIO_HSSR_BED_ATTACK=off` since 25.09; owner mode with collapse 0.75 shipped 22.09): off, so no per-hit collapse and the retention HF taper (default 1000:2500 Hz) is ignored.

### 1.8 Time-domain post chain (`stereo_upmix.c`, per frame, in order)

1. Rear (object + bed) → RBJ low shelf **−4 dB @ 500 Hz** (`AUDIO_STEREO_REAR_BODY_DB` default −4); same shelf separately on the source image.
2. LFE V2 (`AUDIO_STEREO_LFE=assist`): mono of the delayed front input, LR4 **60 Hz** (comments still say 48), anti-phase handling (corr every 32 samples, polarity slew 0.0018/0.00045), dynamic gain 0.96 + 0.08·bass_conf + 0.08·drum_conf + 0.08·transient ≤ 1.10, × 4096/32768 = **0.125 FS** at `AUDIO_STEREO_LFE_GAIN=0` (range −24..+12 dB, cap 16384). The only sub lever; relative to the amp's own sub derivation.
3. Rear → RBJ high shelf **+3 dB @ 4 kHz** (~+1.5 dB at 4 kHz), rear only, not the transfer.
4. Linked rear limiter: instant attack at |rear| > 1.0, release 0.0005/sample (~42 ms), same gain on the transfer.
5. **Rear-only delay 576 frames = 12 ms** (precedence: "front anchors the image, rear reads as a second scene"); transfer uses the undelayed source.
6. front = render × 31392/32768 (**0.958**; 0.997 without LFE assist). rear_out = clamp(rear, ±1) × 13107/32768 (**0.40**; code default 0.18; parser max 0.5). transfer_out = clamp(transfer) × 0.40.
7. Front transfer: front −= transfer_out × 2.5 × (1 − retention 0.5) → **half** of the shelved, projected object is removed from the front (the comment "subtract once" holds only at retention 0).
8. Front-only RBJ low shelf **−3 dB @ 200 Hz** (`AUDIO_STEREO_FRONT_BASS_DB=−3`); front treble shelf @ 4 kHz unset.
9. Frame [L, R, 0, LFE, Ls, Rs] → cabin guard `spa_upmix_cabin_guard_s16`: early-out if peak × 3.53 ≤ 32275 (0.985 FS); else bound LFE first so every J525 input-matrix bus (hook copy `kInputMatrix` 6×8, bank 1 / profile 0, corrected 2026-09-20) stays under 32275, then linked-scale all six channels. 3.53 = effect-bus column (0.708·L + 2.818·Ls).

### 1.9 What each channel receives (summary)

- **Ls/Rs**: 0.40 × [12 ms delayed, limited, +3 dB@4k, −4 dB@500] of (coherent object ≤ 1.45·0.40 = 0.58 of source amplitude, steered to ±0.78..0.95, gated by voice) + (ambience ≤ 0.04 + universal ≤ 0.55·makeup + diffuse, phase-rotated, ≥ 220 Hz) + (static air copy of L/R above 2–4 kHz at −9 dB), all beds decorrelated by the per-band delay comb. **Nothing below 220 Hz** (object, universal and ambience targets are 0 there); rear PCM < 350 Hz measured 40–55 dB under input [offline]. Rear PCM ceiling −8 dBFS by config, max −6 dBFS (0.5).
- **L/R**: the bit-exact input, delayed 10.67 ms, × 0.958, minus half of the shelved object, −3 dB shelf @ 200 Hz. The object is therefore present in the front and (12 ms later, −8 dB, steered) in the rear.
- **C**: 0. **LFE**: 0.125 × LR4-60 Hz mono of the front, cabin-aware.
- In the hssr_dsp domain the rear copy is described as ~20–30 dB under the front [inferred: design-doc statement, not a measurement]; through the route and amp the rear bus comes within 0–5 dB of the front bus above 350 Hz at surround 0.40 [model, pre-transposition-fix numbers, see §1.11].

### 1.10 Route to the amp

Hook → PCM ring (~250 ms, cold prime 400 ms) → QSA `mpl5_dio_ent` (writer SCHED_RR 18, 9216-byte S16 fragments, device 18432-byte S32) → deva-ctrl-qc with the shipped "mirror driver" (MPL5 caps = MPL1: 6 voices, 0x4800 fragment, 24-bit S32) → CSD device 78 (session fixed 6 ch / 24-bit, map 01 02 03 06 08 09) → LPASS COPP 0x10314 (passes 6 ch) → AFE TDM 32-byte frame, media slots at byte offsets 2,5,8,11,14,17 (S16 left-aligned in 24-bit = 16 useful bits, no gain) → MOST150 BlockWidth 26 → J525 sink 0x26 (or 0x32, unresolved) → matrix bank 1 for every ASAD; stereo bank 0 / library mode 2.0 unreachable on this sink. Proven six-wide and clean (SHA-identical PCM, 0 mismatches; centre + surrounds audible 2026-09-03; discrete APAC 5.1 end to end 2026-09-06) [car]. Non-B&O cars have no 6-ch route (BlockWidth 4); `AUDIO_SPATIAL=1` is hardcoded, the E2P 0xFC gate is not implemented.

## 2. Why the rear is faint and unstable

Ranked by weight of evidence. Categories: (a) deliberately withheld, (b) extraction, (c) renderer/route, (d) amp, (e) tuning.

1. **(a) The rear is a −8 dB, 12 ms-late, half-duplicated copy of material the front still plays** — proven by construction [code] and by level [offline/model]. Rear PCM ceiling 0.40 FS vs front 0.958; a fully eligible bin (mask 1.45) reaches 0.58 of the source amplitude in the rear while the front keeps 0.5 of it (retention 0.5, flat). The stated purpose of the 12 ms delay is that "the front anchors the image (precedence)". ## 6. Metrics and their validity

Definitions (tools/stereo-upmix-render):

- **rear share** (`upmix_behavior_tests.rear_share`): STFT 2048/512 Hann of dry lead, dry rest and the 6-ch render; cell owned if dry lead > rest + 10 dB and ≥ 300 Hz (12 bins; comment says 350 Hz); frame = 5 hops = 53.3 ms; share = Σ rear(Ls+Rs) / Σ (FL+FR+C+Ls+Rs) over owned cells; LFE ignored; **no latency alignment** between dry and rendered (renderer latency 22.7 ms vs 43 ms window); `median_rear` = median over active frames (lead-on > 0.9, > 20 owned cells). A ratio: level-independent by design (robustness test enforces −40 dB invariance). 0.15 = rear 7.5 dB below front in those cells; 0.02 = −17 dB.
- **swing**: `range_1s` = max − min of 1 s-window medians of share (body from 2 s); stem-row swings if > 0.30; a song swings if **any** stem does (older tables counted guitar only: x/39 vs x/40). "Relative swing" = range / median share (level-independent; the absolute count grows with level — the 27.09 morning "2/40" was a level metric in disguise).
- **flicker**: `flick250` = std of the whole-mix 2.5–10 kHz rear share at 245 ms frames (music harness); `steady_std` (synthetic); `range1s` in the music harness uses raw 1.0 s frames, not window medians.
- **retention / ducking**: `diag_transitions` v2 — vocal entries from the true vocal stem (2 s RMS rise > 10 dB landing > −40 dBFS), ≤ 3 per kind per song; the mixture-inferred mask is applied to the true eligible and true vocal STFTs; per 0.5 s bin retention = transmitted eligible / eligible (−55 dBFS floor); duck = post(8 s)/pre(4 s); gates median ≥ .85, p10 ≥ .60; leak_0_2, steady, settling p90. Never computed for the shipped C path (eval_tracka: "no attributed vocal-entry/exit").
- **leak / transmission** (`diag_gap` v2): frozen mask on each true stem, reanalysed; eligible/vocal/protected transmission, per-band (8–14 k, > 14 k), IRM reference, bootstrap CIs. Components can cancel in the summed waveform ("sensitivity, not audible content"). Historical v1 vocal-owned bug (max(|X|²−|V|²,0) instead of |X−V|²) corrected read-only.
- **rear RMS** dBFS per song; release screen requires candidate within ±0.5 dB of baseline (`rear_rms_within_half_db`) — **structurally forbids a louder rear**; eval_tracka drops it only because it is its own baseline.
- **slope per 6 dB** (depth follows level) gate ≤ .05; **rear error vs oracle** NSE (±50 ms alignment, gain fit); **band shares** 300–1 k … 10–16 k (whole-excerpt ratios, no temporal median).
- **SI-SDR** (eligible estimate vs true "other"): diagnostic only; repeatedly ranked models opposite to the gates (fine-role SI-SDR up, gates down; vocal-invariance leak .013 = silence). **NMSE**: discredited in 09-17 ("do not judge by NMSE") yet the joint-scene gate (rear NMSE ≤ .10 vs 1.0 silent) — a contradiction the docs note. **AUC / mask space**: ranking, not calibration. **bed_metrics**: Ls/Rs MSC per band, attack smear (0–10 vs 10–40 ms after onset, latency 512+576 assumed), "not a listening result"; attack-smear cannot separate bed variants (±0.1 dB).
- Amp-side: 60 s level-matched bus/seat spectra from AmpChain (electrical, bank 1 / profile 0 / B = 0 / 3D OFF assumed); `release_acceptance.py` v2 seals hashes and refuses computed proxies for TARGET/LISTENING/CABIN gates.

## 9. Levers and facts a redesign must weigh

What "strong rear scene + front kept" requires physically (from the evidence, not a design):

- **Energy must move or be different.** Adding rear without removing from the front moves nothing (C2: front +2–3 % louder; the current rear is a −8 dB delayed duplicate the precedence effect fuses back to the front). Two honest options exist in the evidence: (i) remove the object's source-aligned estimate from the front (retention → 0) — only valid with a clean estimate (C2 at 70 % removal: F/F0 0.12–0.17, R/F 3.9–5.0; never listened); (ii) put **different** content in the rear — decorrelated/diffuse (Dolby reference: only the residual goes rear, transients pulled forward; PAD/matrix baselines; the air bed) which is static and stable by construction. Energy bound r* = √(1−b²) = 0.917 at b = 0.40 is already where the object localises front (7.2 dB louder and 12 ms earlier): an upper bound, not a safe region.
- **Static beats steered for stability.** Every dynamic rear decision (slots, ridge, coherence, attack, taper, gate, per-cell e) carried flicker; the air bed and a fixed per-bin gain on an isolated object did not. "Strong" via the current object path = more voice and swing (drive 1.7, G 1.6, surround 0.5 all proven); a rear built as G × eligible audio with no projection was static (0/40) at .3235 for every source, and at .40 only when the audio was clean (2/40 exact vs 27–33/40 learned).
