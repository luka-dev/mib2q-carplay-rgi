# MoisesDB Instrument-Family Sidecar — Preparation

_Track B, 2026-09-29. CPU data preparation and first real-song gate; full TRAIN build underway._

The current seven-slot truth cache folds guitar, piano, keys, strings, winds and residual instruments into slot 6 (`other`). A read-only scan of `data.json` for the **176 present TRAIN caches** found recorded `stemName` roles in **159 guitar**, **85 piano**, **73 other_keys**, **32 bowed_strings** and **21 wind** songs. These are overlapping song counts. The raw labels support a genuine instrument-family remix without guessing from filenames.

[`cache_moises_instruments.py`](../../tools/stereo-upmix-render/cache_moises_instruments.py) prepares a six-slot **TRAIN-only** sidecar: guitar, keys, piano, strings, winds and residual other. It excludes the existing protected MoisesDB roles (vocals, drums, percussion and bass), reads the raw 44.1-kHz stereo WAVs and reproduces the existing cache's 48-kHz resampling. It estimates the original song normalization from the saved seven-slot cache, then requires the six quantized sidecar slots to sum **exactly** to its original slot 6. Before a small quantization-residual correction, it rejects RMS mismatch above 3 PCM LSB or peak mismatch above 100 LSB. The correction is confined to the residual `other` slot and must fit int16; any failed song stops the build for inspection. No DEV/TEST stem is written.

A synthetic 2-second song with seven eligible source files passed the parser/resampler/scale path with **1.47 LSB** pre-correction RMS and **6 LSB** maximum residual; post-correction closure was exact. This is a code smoke check, not proof that all real MoisesDB songs fit. The builder writes each song atomically and skips completed shape-checked sidecars on resume (`--force` rebuilds one). The first PC action after the OnAir pair ends is `--one` on a cached TRAIN song, reporting roles, sample rate and residual. Only then decide whether to build all 176 sidecars. The PC has about 1.2 TB free, but a full sidecar build will read and write many gigabytes on WinBtrfs, so it must not overlap the active GPU experiment.

The subsequent network intervention is separate from the cache build: compare the existing four-family MoisesDB remix with the **same** model, seed, ratio and training age while drawing its eligible guitar/keys/piano/strings/winds/other families from independent TRAIN songs. Preserve the protected-family sampling and natural-song DEV/real-C evaluation in both arms. An optional `--instrument-sidecar DIR` path in `sep_net.py` is staged locally for exactly that replacement inside `--remix` windows; a synthetic sampler test verified mixture = eligible + vocal + drums + bass. It has **not** been copied to the PC or trained, and the failed 4k four-family remix does not decide its outcome.
