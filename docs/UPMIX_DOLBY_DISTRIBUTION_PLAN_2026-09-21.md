# План: перенос трёх принципов распределения остатка Dolby в HSSR (2026-09-21)

Статус: **план, ничего не реализовано.** Калибровка в машине заморожена решением
Luka 21.09 (см. handoff). Всё ниже — работа над следующей версией сцены: сначала
офлайн, в машину только по слову Luka, переключение через env при подключении
телефона, без перезагрузки. Каждый новый механизм — отдельный env-флаг,
по умолчанию выключен, при выключенном флаге выход бит-в-бит равен текущему.

Источники: [Dolby SYNTHESIS](../output/r2/dolby-surround/SYNTHESIS.md) и
`kernel-probes.json` (матрицы, задержки, детектор атак);
[60-секундный грид](UPMIX_LONG_ONEVAR_2026-09-21.md); код
`hook/audio/hssr_dsp.c` (`spa_hssr_render_hop`) и `hook/audio/stereo_upmix.c`.

## 0. Что у нас сейчас и почему нельзя копировать Dolby целиком

HSSR (FFT 512, hop 128 = 2,667 мс, 257 бинов, 32 полосы) в каждом бине собирает тыл
из трёх слагаемых:

| Слагаемое | Откуда | Вычитается из фронта? | Уровень |
|---|---|---|---|
| **объект** `mask·steer·proj` | когерентный панорамированный объект, разрешённый семантической маской | **да, полностью** при retention 0 (2,5·0,40 = 1,0) | тыл ×0,40 |
| ambience `±ambience·side` | небольшой side-bed | нет | ≤ 0,04 |
| universal bed (rotated mid, фиксированный фазовый поворот на бин) | «нет мёртвого тыла» + диффузный слой (некогерентное, ≥ 220 Гц) + percussion_safety | нет | ≤ 0,55·makeup |

Dolby никогда не переносит доминирующий объект назад: направленная часть остаётся
там, куда указывает, а назад идёт **только остаток** (и противофаза). Наш «второй
план» (объекты сзади) — сознательно другой продукт, который Luka принял.
Поэтому принципы Dolby раскладываются так:

- принцип 1 (сохранение энергии) применяется к **объекту** через уже существующий
  retention, без кода;
- принцип 2 (задержки по частоте) применяется к **bed**, нашему аналогу остатка
  Dolby; объект по бинам не задерживать, он должен оставаться когерентным;
- принцип 3 (атаки) = собрать удар в одну точку; у Dolby всегда вперёд, у нас туда,
  где владелец полосы: объект второго плана → назад, без владельца → вперёд.

## 1. Сохранение энергии при переносе объекта (кода нет)

Для маскированной доли объекта `m·obj`: фронт оставляет `r·m·obj`, тыл получает
`b·m·obj`, где `r` = `AUDIO_STEREO_FRONT_RETENTION`, `b` = `AUDIO_STEREO_SURROUND`.
Энергосохраняющая точка: `r* = sqrt(1 − b²)`.

| b (тыл) | r* | фронт-доля объекта |
|---:|---:|---:|
| 0,30 | 0,954 | −0,4 дБ |
| **0,40 (сейчас)** | **0,917** | **−0,75 дБ** |
| 0,50 | 0,866 | −1,25 дБ |

При r = 0,917 объект по прецеденту (фронт громче на 7,2 дБ и раньше на 12 мс)
локализуется впереди — «второй план» исчезает. Значит r* это не цель, а верхняя
граница. Задача: найти максимальный r, при котором объект всё ещё читается сзади.

Эксперимент (офлайн, потом уши):

1. Рендеры r ∈ {0,50; 0,917} на том же 60-секундном гриде (уже есть 0 и 0,75):
   `--variant ret50:s16:0.40:-3:0:0.5 --variant ret92:s16:0.40:-3:0:0.917`,
   14 строк ≈ 55 мин при `--jobs 3`. Ожидание по измеренным дельтам: фронт-середина
   +1,5 / +3,0 дБ, тыл +0,7 / +1,4, центр +2 / +4, пики до +1…+2 дБ.
2. Прослушивание A/B (r = 0 / 0,5 / 0,75) при MMI Bass 0 / Sub 0: критерий один —
   объект ещё сзади или уже спереди. Правило выбора: наибольший r, где «сзади».
3. Не делать: общий makeup-gain после переноса (+3 дБ) — пики модели уже +4,7 dBFS,
   запас усилителя неизвестен.

## 2. Задержки по частоте и перекрёстный член для bed (код в `hssr_dsp.c`)

Dolby: остаток разложен на потоки с задержками, разными по бинам (единица = вызов
ядра; гипотеза 64 отсчёта = 1,33 мс, тогда НЧ 32–43 мс, низкая середина 19–27,
середина 8–16, верхняя середина 2,7–10,7, ВЧ 2,7–5,3 мс), плюс перекрёстный член
−0,123/0,681 ≈ −0,18 между surroundA/B. Наш фиксированный фазовый поворот на бин
(12–45°) это субмиллисекундный эффект, не декорреляция такого масштаба; общая
задержка 12 мс одинакова для Ls и Rs и остаётся для объекта (прецедент).

Изменения в `spa_hssr_render_hop` (после композиции бинов, до обратного FFT):

1. Разделить накопление: `fft_*[ch][bin]` = объект (`mask·steer·proj`), новый массив
   `bed_re/im[2][257]` = ambience + universal. Сейчас они складываются в одно место.
2. Кольцо задержки bed по бинам: `bed_ring_re/im[2][16][257]` (16 hop = 43 мс,
   2·16·257·2·4 B = 66 КБ в `struct spa_hssr_dsp`), индекс hop по кругу.
3. Таблица задержек в hop (2,667 мс), L и R разные, убывают с частотой:

| Полосы (индексы) | Гц | Ls, hop / мс | Rs, hop / мс |
|---|---|---:|---:|
| 0–4 | 0–220 | 12 / 32 | 15 / 40 (bed здесь ≈ 0 по построению) |
| 5–9 | 220–680 | 9 / 24 | 7 / 18,7 |
| 10–13 | 680–1450 | 4 / 10,7 | 6 / 16 |
| 14–17 | 1450–3000 | 2 / 5,3 | 3 / 8 |
| 18–31 | 3000–24000 | 1 / 2,7 | 2 / 5,3 |

4. Смешивание: `rearL += bedL[t−dL] − 0,18·bedR[t−dR]`, `rearR += bedR[t−dR] − 0,18·bedL[t−dL]`
   (масштаб `1/sqrt(1+0,18²)`, чтобы энергия bed не росла).
5. Флаг `AUDIO_HSSR_BED_DELAYS=0|1` (default 0) → `config.bed_delays`; при 0 путь
   обходится и выход бит-в-бит прежний. Хост-рендерер: `--bed-delays`.
6. Тест в `tests/stereo_upmix_test.c`: (a) флаг 0 → существующие universal-тесты
   зелёные без изменений; (b) флаг 1, синтетика с bed и без объекта → импульсный
   отклик тыла показывает ожидаемые hop-задержки по полосам и перекрёстный член;
   (c) reset очищает кольцо.
7. Метрика офлайн (по PCM6, без модели усилителя, секунды на трек): когерентность
   Ls/Rs по полосам (Welch, MSC). Ожидание: падение в 220 Гц–3 кГц против базы.
   Утечка лида: тыл/фронт в 300–3000 Гц не должна расти (bed не трогает маску).

Пятипотоковый вариант Dolby (V2–V4 как суммы R0/R1 с разными задержками) — отложен;
два задержанных потока + перекрёстный член сначала.

## 3. Атака = собрать удар в одну точку; куда — решает владелец полосы (код в `hssr_dsp.c`, требует п. 2)

Формулировка Luka 21.09: смысл механизма атак не «вперёд», а **в кучу**: удар
должен прийти из одного места, не из двух с задержками. У Dolby остаток не имеет
владельца, поэтому он всегда собирается вперёд (доля R0 в surround 0,54 → 0,21, во
фронт 0,55 → 0,85). У нас владелец полосы известен: слоты объектов и маска.

Детектор по полосам как у Dolby: `H ← β·H + (1−β)·E`,
`target = clamp(0,5017·log2(0,5012·E/H), 0, 1)` (0 при ≤ +3 дБ, 0,5 при +6, 1 при
≥ +9 дБ), `w = max(target, β·w)`, β за hop = 0,98169² = 0,9637 (≈ 73 мс при
гипотезе 64 отсчётов на единицу). `E_b` из `bands[b]`, история `band_slow_energy[b]`.

Владелец: `owner_b = smoothstep(best_score_b, 0,04, 0,28)` (тот же порог, что у
`object_absence` в `render_hop`), агрегированный по бинам полосы за hop.

Правило сборки, линейная интерполяция усилений по `w_b` (один и тот же сигнал,
меняются только коэффициенты, поэтому power-нормировка Dolby не нужна):

| Состояние полосы | Стационар | Атака (w → 1) |
|---|---|---|
| есть объект второго плана (`owner_b` → 1) | объект: фронт `r`, тыл `b`; bed без и с задержкой | объект **собирается сзади**: `r_eff = r·(1 − c·w)`, задержанные копии bed × `(1 − w)` |
| владельца нет (`owner_b` → 0) | bed в тыл без и с задержкой | **собирается спереди**: задержанные копии × `(1 − w)`, недержанный bed в тыл × `(1 − 0,61·w)` (0,39 при w = 1, как у Dolby) |

`c` = глубина сборки назад (0…1), один экспериментальный knob; при `c = 1` и
`r = 0` ничего не меняется для объекта (он и так весь сзади). Смысл `c` появляется
только вместе с п. 1 (r > 0): в стационаре объект делится фронт/тыл, на ударе
на ~70 мс уходит целиком назад. Риск: слышимое «проседание» фронта на каждом ударе;
решает прослушивание, поэтому knob, а не константа.

Для этого retention должен переехать из `stereo_upmix.c` (глобальный скаляр во
времени) в STFT-домен: `source_fft[bin] *= (1 − r_b(t))`, а `transfer_amount` в
`stereo_upmix.c` при включённом флаге = 1 (и float, и S16 ветки). Без флага —
прежний путь, бит-в-бит.

Конфликт с `percussion_safety` (bed поднимается на транзиентах в ударных полосах,
барабаны сзади — часть принятого «второго плана») этим правилом снят: ударные
полосы с владельцем собираются назад, без владельца — вперёд; в обоих случаях
режутся только задержанные копии, то есть само размытие.

1. Флаг `AUDIO_HSSR_BED_ATTACK=off|owner|front` (default off; `front` = чистый режим
   Dolby, всё вперёд, для сравнения), `AUDIO_HSSR_ATTACK_COLLAPSE=c`. Хост:
   `--bed-attack`, `--attack-collapse`.
2. Тест: стационар → скачок ×4 (+12 дБ) → стационар даёт `w = 0, 1, β, β², β³`
   (как в Dolby-пробе); пороги +3/+6/+9 дБ → 0 / 0,5 / 1; синтетика с объектом в
   слоте → на ударе фронт-доля объекта падает до `r·(1−c)`, без слота — тыл bed ×0,39.
3. Метрика офлайн: размытие атак — по онсетам dry (пики спектрального потока)
   энергия тыла в окне 10–40 мс после онсета относительно 0–10 мс, по полосам;
   ожидание: ниже базы. Плюс «единственность источника»: доля энергии удара в
   первых 10 мс, приходящаяся на один из двух планов (фронт или тыл), должна расти.
   При `front` дополнительно смотреть, не пропали ли ударные сзади (rear 2–8 кГц).

## 5. Что ещё не доказано у Dolby и влияет на числа

- Период вызова ядра (единица задержек): гипотеза 64 отсчёта. Проверка статикой в DLL:
  hop банка анализа 77 бинов и число вызовов `0x18005a9f0` на блок 1024. Если единица
  1024 отсчёта, задержки 64–660 мс — это не декорреляция, таблицу п. 2 пересмотреть.
- Какой режим (2 или 5 потоков) активен в пользовательском профиле; ветка `0x18004df60`.
- Соответствие 77 бинов частотам (границы полос известны, центры не доказаны).

  мал. Чтобы измерить смаз bed, нужен рендер bed отдельно (объект замьютирован) либо
  прослушивание. Это ограничение метрики, не доказательство отсутствия эффекта.

## 7. Машина: фронт стал ярче, и почему (2026-09-21, после деплоя)

Luka на машине: «высоких стало многовато, особенно на первом потоке (Spotify);
проблема не в тыле, а в том, что во фронте высокие стали громче; всё остальное
звучит очень неплохо». Замер offline подтвердил жалобу и указал причину.

4 трека × 60 с, тот же нативный рендерер, PCM6 без модели усилителя, полосы по
каналам, среднее по трекам. База A = retention 0 + `--bed-delays` (как было до
работы над атаками), B = задеплоенное retention 0,5 + `owner` + c 0,75:

| Полоса / канал | B − A |
|---|---:|
| 0,5–2 кГц фронт L/R | +1,31 / +1,43 |
| 2–8 кГц фронт L/R | +1,32 / +1,23 |
| 8–16 кГц фронт L/R | +1,04 / +1,02 |
| 2–8 кГц тыл Ls/Rs | −0,18 / −0,21 |
| центр (все полосы) | 0,00 |

То есть retention поднимает фронт **широкополосно**, а не только в теле: объекты
(лид, вокал, тарелки) яркие, и половина объекта, оставленная во фронте, приносит с
собой свой верх. Тыл при этом не растёт, поэтому сумма ВЧ в кабине уезжает вперёд.
Жалоба — прямое следствие выбранного retention 0,5, а не ошибка в атаках; атаки лишь
модулируют эту долю на каждом ударе.

**Исправление:** retention сделан частотно-зависимым. Доля объекта, остающаяся во
фронте, катится вниз от `retention_hf_lo_hz` и равна нулю с `retention_hf_hi_hz`;
весь множитель `1 − r(f)·(1 − c·w·owner)` считается один раз на полосу в
`band_front_keep[]`, а 257-бинный цикл только читает его (на 5 арифметических
операций на бин меньше; ARM icount 7 821 376 → 7 809 633, −0,15 % на пути с
выключенными атаками, больше на боевом пути).

Замер тейпера, те же 4 трека, всё остальное = B:

| retention-hf | 0,5–2 кГц фронт | 2–8 кГц фронт | 8–16 кГц фронт | тыл |
|---|---:|---:|---:|---:|
| выкл (= B) | +1,31 / +1,43 | +1,32 / +1,23 | +1,04 / +1,02 | без изменений |
| 2000:6000 | +1,31 / +1,43 | +0,81 / +0,73 | −0,00 | без изменений |
| 1500:4000 | +1,30 / +1,43 | +0,41 / +0,36 | −0,00 | без изменений |
| **1000:2500 (дефолт)** | **+1,21 / +1,35** | **+0,04** | **−0,00** | **без изменений** |

Выбран 1000:2500: верх во фронте возвращается к состоянию «до retention» (+0,04 дБ),
а тело сохраняет 92 % прибавки (+1,21 вместо +1,31). Тыл во всех вариантах бит-в-бит
тот же — тейпер касается только вычитания объекта из фронта.

Ручка: `AUDIO_HSSR_RETENTION_HF=LO:HI` (Гц, `HI <= LO` = выключить, т.е. прежнее
поведение). Дефолт зашит в код (`SPA_STEREO_UPMIX_RETENTION_HF_{LO,HI}_HZ`), так что
подмены `.so` достаточно, перезагрузка не нужна; env меняется только с перезагрузкой.
Проверки: `--retention-hf 0:0` даёт `cmp`-идентичный выход прежнему бинарнику на всех
4 треках; `tests/stereo_upmix_test.c::test_retention_hf_taper` требует равенства
полос ниже 1000 Гц, `keep == 1` с 2500 Гц, бит-в-бит тыл и отличие фронта.
