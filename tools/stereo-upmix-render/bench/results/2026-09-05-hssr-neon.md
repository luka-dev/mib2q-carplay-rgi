# HSSR-NEON development checkpoint — 2026-09-05

## Candidate

The implemented `hssr-neon` backend uses a causal 512-point STFT with 128-frame
hop, 32 semantic bands, a 368-value feature vector, and a two-layer GRU with
160 hidden units per layer. The model produces 264 control values at 93.75 Hz;
waveform routing and reconstruction remain deterministic DSP. The exported
int8-weight development model contains 451,464 parameters and is 469,760 bytes.

The selected renderer applies semantic makeup 6 after a cubic lead-vocal veto,
quadratic bass veto, and main-drum/foreground guards. Digital C remains zero.
Fronts, rears, and optional LFE share an exact 512-frame (10.67 ms) delay. The
accepted rear component is subtracted from the matching front at -3 dB, so the
canonical stereo fold is preserved apart from fixed front trim and S16
rounding/safety bounds.

The model in `build/hssr/hssr_model.bin` is trained from MUSDB audio and is
development-only. It must not be shipped commercially without licensing
clearance or retraining on cleared stems.

## Numerical parity

One 6.8-second held-out track was decoded to S16 and processed independently by
the Python and C feature extractors:

- 637 control frames;
- mean absolute feature error: 0.00003097;
- P99 absolute feature error: 0.000683;
- maximum absolute feature error: 0.03125.

Against the FP32 PyTorch checkpoint on the same sequence, exported C inference
has 97.29% semantic-class agreement and mean rear-probability error 0.00644.
The regression suite includes a dedicated guard against aliasing layer-two
input with its recurrent state.

## Live ARMv7/QNX timing

Measured over SSH on the APQ8064/Krait head unit with the GCC 8.5 QNX build.
The benchmark processes 1024 input frames per call; its realtime deadline is
21.333 ms. QNX `CLOCK_MONOTONIC` advances in roughly 1.007 ms steps on this
unit, so percentile values are quantized; the 512-call aggregate mean is the
more useful number.

| backend | mean | P95 | P99 | max | mean deadline share |
|---|---:|---:|---:|---:|---:|
| `music-stage` | 1.812 ms | 3.022 ms | 4.029 ms | 6.043 ms | 8.49% |
| `hssr-neon` | 4.283 ms | 6.043 ms | 8.057 ms | 9.065 ms | 20.07% |

The full HSSR backend therefore adds about 2.47 ms per 1024-frame packet over
`music-stage` and remained below 42.5% of its deadline in this run. The test
copied only the benchmark and model to `/tmp`, did not restart audio services,
and removed both files afterward.

The final hook is 32-bit ARMv7 and contains the expected `vmull.s8` and
`vpadal.s16` NEON instructions. Local artifact hashes:

## Offline routing evaluation

All rows use rear gain 0.25 and LFE assist. The controlled set contains 24
held-out MUSDB stem renders. Public authored rows contain six independently
published stereo/5.0 classical pairs. Apple rows use six public Apple Music
preview masters aligned to the same authored surround recordings; master
differences make those waveform scores conservative.

### Controlled 24-track held-out aggregate

| backend | rear envelope corr | rear waveform corr | rear SI-SDR | L/R corr error | rear RMS ratio | front SNR | fold SNR |
|---|---:|---:|---:|---:|---:|---:|---:|
| `hsr-td-active` | 0.382 | 0.393 | -8.28 dB | 1.007 | 0.122 | 25.72 dB | 75.60 dB |
| `music-stage` | 0.430 | 0.436 | -6.79 dB | 0.737 | 0.151 | 23.14 dB | 75.59 dB |
| `hssr-neon` | 0.376 | 0.559 | **-3.40 dB** | **0.197** | 0.117 | 25.15 dB | 75.60 dB |

HSSR gains 3.39 dB rear SI-SDR over `music-stage` and greatly reduces the
Ls/Rs correlation error while retaining similar rear level and better front
preservation. This supports semantic routing, but does not replace listening.

### Public programme aggregates

| corpus/backend | rear envelope corr | rear SI-SDR | L/R corr error | rear RMS ratio |
|---|---:|---:|---:|---:|
| authored pairs / `music-stage` | 0.765 | -8.22 dB | 0.388 | 0.456 |
| authored pairs / `hssr-neon` | 0.199 | -8.35 dB | **0.209** | 0.230 |
| Apple previews / `music-stage` | 0.785 | -17.76 dB | 0.377 | 0.477 |
| Apple previews / `hssr-neon` | 0.661 | **-17.25 dB** | **0.217** | 0.291 |

The classical authored set exposes a current weakness: HSSR is conservative on
long ambient orchestral beds, so its rear envelope follows those references
less closely. The Apple-master comparison nevertheless improves SI-SDR and
channel geometry slightly. Future training needs commercially cleared
classical and electronic stems rather than a louder generic ambience fallback.

### Isolated-stem safety probe

Eight held-out MUSDB tracks were rendered one stem at a time. Rear power is
reported relative to input power; lower is safer for protected content.

| stem | mean | worst track |
|---|---:|---:|
| vocals | -22.9 dB | -15.2 dB |
| bass | -32.5 dB | -26.5 dB |
| drums | -26.7 dB | -23.3 dB |
| other | -16.3 dB | -12.9 dB |

MUSDB combines lead and backing vocals in one stem, so the vocal worst case is
not a proof of lead-vocal leakage. It is a mandatory listening focus before
deployment.
