# CUpGAN disclosed-core benchmark - 2026-09-04

Source revision: working tree based on `83d1145`. Only the isolated files under
`tools/cupgan-bench/` participate in these numbers.

Scope: four dense conditioned ConvNeXt blocks over `(21, 513, T)`. The
benchmark excludes STFT/iSTFT, the input IBN, final output projection and the
control net. Pseudo-weights exercise the disclosed tensor shapes but have no
audio meaning.

## Static result

- Conventional padded count: 7,627,284 MAC per 512-sample hop.
- At 48 kHz: 715.058 million MAC/s.
- Paper figure scaled from 44.1 to 48 kHz: 287.347 million MAC/s.
- Disclosed-core count divided by scaled paper figure: 2.488x.
- Scalar model storage: 62,832 bytes; manual-NEON packed storage: 66,864
  bytes; streaming/scratch state: 861,844 bytes.

## Host floor

Machine: Apple M3 Max, Apple clang `-O3`.

Command:

```sh
tools/cupgan-bench/build_host.sh
build/cupgan/cupgan_bench_host --frames 256 --warmup 8
```

Result: mean 1.934 ms/hop, p99 2.169 ms, max 2.198 ms. This consumes 18.13%
of one local core's 10.667 ms hop interval. It is not an ARMv7 estimate.

## QNX 6.5 / ARMv7 instruction count

Compiler: `arm-unknown-nto-qnx6.5.0eabi-gcc` 8.5.0. Guest: QNX 6.5
armle-v7 under QEMU `-icount shift=0`. The guest calibration classified
`ClockCycles()` as an instruction counter at about 15.946 instructions/tick.

| code generation | instructions/hop | instructions/audio-second | one 1.7 GHz core, IPC 1.0 | result |
| --- | ---: | ---: | ---: | --- |
| scalar, shipping-like `-O2` | 48,900,912 | 4.584 billion | 269.7% | impossible |
| GCC 8.5 manual packed NEON, `-O3 -ffast-math` | 17,996,681 mean; 17,997,241 p99 | 1.687 billion | 99.2% | no product headroom |

The manual-NEON row used eight measured hops after two warm-up hops. Guest
ticks were 1,128,571.9 mean and 1,128,607 p99/max. The spread is negligible,
as expected from instruction counting.

At IPC 0.6 / 1.0 / 1.4 the manual-NEON core alone consumes respectively
165.4% / 99.2% / 70.9% of one 1.7 GHz core. One 1024-frame hook callback
contains two model hops, so the core alone represents about 21.17 ms of CPU at
IPC 1.0 or 15.12 ms at IPC 1.4. The existing 5 ms callback gate is missed
before any unspecified model stage, audio conversion, APAC/AAC work or system
scheduling is added.

Conclusion: GCC 8.5 plus straightforward manual NEON is much better than
scalar (2.72x fewer instructions), but it does not make the disclosed dense
architecture deployable on the current APQ8064 path. A reference implementation
that reconciles the paper's MAC count, much more aggressive kernel work,
quantization/pruning, or a smaller retrained model is required before product
integration is reasonable.
