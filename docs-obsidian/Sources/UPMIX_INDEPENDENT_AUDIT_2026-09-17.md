## Вердикт

**Текущая архитектура не может дать музыкальный продукт, и это видно из уже
запечатанных данных, без ожидания текущего эксперимента.** Модель после полного
прохода равна MUTE плюс ударные. Ни одна голова, нужная для тыла (backing_vocal,
keys, secondary guitar, перкуссионные текстуры), не отделяется. Метрика и контроли
устроены так, что это не бросается в глаза. Текущий запуск (carrier 0 vs 0.1)
стоит дать закончить, он дешёвый и ограниченный, но следующий эксперимент должен
менять сепаратор и данные, а не коэффициент.

Четыре факта, которые меняют трактовку из handoff:

1. **Контроль raw-scalar математически равен инициализации модели.** Прайор
   `‖s_k‖²/Σ‖s_j‖²` совпадает с raw-scalar в пределах 0,11 дБ на всех семействах;
   `mask_head` и `refinement_head` стартуют нулями (`q2_local_guidance_model.py:262-274`),
   `mask_bias` = prior (`q2_power_guidance_model.py:70-72`), контракт
   `initial_predicted_parity='mathematical prior*X'`. «−0,1 дБ к скаляру» означает:
   после 24 288 обновлений модель на DEV стоит там, где стартовала.
2. **Ветка disabled равна MUTE** (медиана +0,004 дБ, p10 −0,15, p90 +0,09).
   «+0,45 дБ над disabled» это сравнение с пустым контролем. Абляция переключает
   только 168 параметров `hint_film` (`q2_local_guidance_model.py:415`).
3. **55 % ячеек (250 из 456) отброшены порогом −40 дБ** (`q2_source_score.py:75-77`).
   Это ровно те ячейки, где живёт утечка в тыл. Их абсолютная мощность сохранена
   в `whole_song_coverage`, но нигде не суммируется. Голова keys выдаёт фантом
   на −12,8 дБ от микса на 12 песнях без клавишных; настоящая партия клавишных
   в этом же DEV в медиане на −15,2 дБ. Голова backing_vocal выдаёт один уровень
   (−54,8 / −55,7 dBFS) независимо от наличия бэков.
4. **Выходы на 13–17 дБ тише цели.** Это сжатие MSE-оценки к нулю при
   неспособности объяснить сигнал, не «консервативность».

Прочее по метрике (`q2_full_song_score.py`, `q2_source_score.py`,
`summarize_q2_full_source.py`): арифметика, выравнивание по FIFO и обработка
нулей честные, ошибок не найдено. NMSE взвешен по мощности по времени, тихие
интро и брейкдауны почти не весят. `coherent_transfer` β считается
(`q2_source_score.py:93`), но не суммируется, а именно он флагирует
«масштабированный микс». Заголовочная медиана «all» балансирует семейства внутри
песни: drums +1,9 компенсирует keys −2,6. По-семейная «медиана песни» при двух
каналах равна min(L,R) (`summarize_q2_full_source.py:76-78`), консервативно, но
недокументировано. Эффективный N ≈ 8 артист-кластеров; все 4 электронные песни
одного артиста (Fröst), жанровый вывод невозможен.

## 4. Разбор цепочки

### Данные (`q2_source_data.py`, [data audit](UPMIX_RELEASE_DATA_AUDIT.md))

Правильно: artist-disjoint split, точный SRC 160:147, закрытие mix = Σ стемов,
запечатанный TEST (`test_pcm_accessed:false` везде).

Мешает:

- **100 из 181 TRAIN-песен выброшены целиком** за один трек с `has_bleed`
  (`admission_reasons`, `q2_source_data.py:68-73`). У 52 из них загрязнён ровно
  один трек, у 28 два. Потеряно 6,4 ч из 10,86 ч. По головам в TRAIN:
  backing_vocal 36 песен / 2,28 ч (при полном допуске 83 / 5,33), keys 57 / 3,14
  (132 / 7,75), strings_winds 18 / 1,12 (54 / 3,40), other_vocal 1 / 0,06,
  other_plucked 1 / 0,06. В DEV: keys 7 песен, percussion 3, strings 1,
  other_vocal и other_plucked 0.
- **Вход = сырая сумма стемов** (`q2_source_data.py:262`), без мастеринга,
  bus-компрессии и лимитера. В машине придёт мастер. Ни один документ этот
  разрыв не признаёт.
- **Аугментаций ноль**: только перестановка песен по эпохам
  (`train_q2_full_source.py:120-134`), reader запрещает independent gain
  (`q2_source_data.py:290`).
- Голова keys неоднородна: grand_piano 31, synth_pad 24, synth_lead 22, organ 8,
  e-piano 7 треков.

Переделать: **по-головный допуск с bleed**. `reconstruction_known` уже вектор по
головам (`q2_source_data.py:135`), loss уже маскирует по головам
(`q2_training_core.py:75`). Меняется только `admission_reasons`/`build_index`,
модель не трогается. Плюс gain ±6 дБ на стем, L/R swap, полярность, dropout стемов,
имитация мастеринга на входе. other_vocal и other_plucked слить в other_unknown.

### Supervision (`q2_training_core.py`, `q2_stream_training.py`)

Loss = complex MSE (1) + magnitude L1 (0,1) + activity BCE (0,05) + descriptor
smooth-L1 (0,05) + uncertainty (0,01), всё в STFT, без PCM и без ограничения
суммы к миксу (`q2_training_core.py:68-100`).

Мешает:

- Головы с UNKNOWN по детекции (hats внутри `full_acoustic_drumkit`, lead/backing
  при `other_vocal`, все 11 голов при стеме `other`, `q2_source_data.py:56-66`)
  всё равно получают **жёсткий ноль как аудио-цель**, потому что аудио-loss
  смотрит только на `known`, который всегда True. Шум меток ровно на слабых головах.
- Знаменатель NMSE локален для 6-секундного чанка (`q2_stream_training.py:197`,
  `train_q2_full_source.py:463`) и отличается от eval (`q2_training_core.py:50`).
- Нулевая инициализация readout-ов: энкодер сначала формируется только
  descriptor-loss через pooling, то есть учится суммировать полосы, а не разделять.

### Детектор (`q2_local_guidance_model.py:104-141, 385-416`)

Сырые квадратуры `[Lre,Lim,Rre,Rim]/√1024`, нормировка кадра по одному самому
громкому бину (`:397-398`): kick сжимает признаки всех остальных бинов к нулю.
32 полосы × 5 признаков → Linear(31→48) → 4-кадровые блоки → cross-band
bottleneck (73 728 параметров, 66 % модели) → один GRU(48) на все полосы → 7 чисел
на источник на полосу. Удерживается 4 кадра без интерполяции (зиппер 21 мс).
Из 111 132 параметров 107 436 здесь. Структурно слеп к lead/backing и keys/guitar,
см. §3. Дообучением не спасается.

### Сепаратор (`q2_local_guidance_model.py:427-443`, `q2_power_guidance_model.py:112-135`)

Разделением занимаются **2 352 параметра**: `mask_head` 1 152, `mask_bias` 48,
`refinement_head` 1 152, поверх общего энкодера 1 344 параметра (почти линейный
фильтр ±2 бина × 31 кадр). Выход источника k:
`(mask_bias_k + dyn_k + w_k − p_k)·X + residual_k`. Все слагаемые функции X,
супервизируется только сумма, разложение неидентифицируемо. Оптимизатор свободно
использует `bias_k<0` или `residual_k ≈ −c·X` для компенсации `w_k`.
«Компенсация ошибок декодера» из handoff это симптом такой структуры, не вред
подсказок. Пришпиливание `w_k` к истинной доле (candidate, coefficient 0,1)
ломает со-адаптированные смещения, и отсутствующие головы текут, пока остальные
слагаемые не пере-адаптируются. Лечится структурой, не коэффициентом.

Переделать: per-bin softmax-маска по 12 источникам (сумма к миксу бесплатно,
отсутствующие головы уходят в ноль сами), вход log|X_L|, log|X_R|, ILD, IPD,
causal band-split GRU с контекстом по частоте, ~1 M параметров. Тот же класс MAC,
синтез на runtime только тыла: 2 iFFT вместо 24.

### Роли ([role targets](UPMIX_Q2_ROLE_TARGETS.md), `q2_role_targets.py`, `vocal_role_policy.py`)

Ноль человеческих меток, `votes_created: 0`. У модели `role_prediction_implemented=False`
(`q2_local_guidance_model.py:33-37`), вход только STFT микса. Матрица разрешений
`[N,12]` подаётся снаружи; единственные производители в дереве это тестовые
фикстуры (`q2_session_chain_vectors.py:72-78`). Это отсутствующая стадия, не
«мешающая». Для исследовательского кандидата допустим class-default с явной
пометкой; для продукта нужны реальные интервальные метки.

### Рендерер (`q2_common_output.py`, `q2_session_chain_native.c:377-389`, `c2_scene_renderer.py`)

Правильно: фронт = сухой оригинал с задержкой 1024, C/LFE = 0, один общий gain,
один лимитер, один квантайзер, транзакционный откат.

Мешает:

- Тыл = `0,35·Σ p_k·HP120(h_k)`, HP первого порядка (6 дБ/окт, 120–250 Гц почти
  не режется), **без задержки, декорреляции и вычитания** (`source_removal=0`,
  `electrical_front_correction=0`, `q2_common_output.py:36,141`;
  `no_panning_or_decorrelation=True`, `c2_scene_renderer.py:36`). Тыл это
  когерентная копия с нулевой задержкой того, что на 100 % остаётся спереди.
- Заводская матрица (`hook/audio/stereo_upmix.c:55-62`): `bus_L = 0,794·L + 0,708·SL`,
  `bus_Ls = 1,995·SL`. При p=1 «разрешённая» компонента становится громче спереди
  на +2,4 дБ в фазе, сзади идёт копия на −3,5 дБ, суммарно +4 дБ энергии.
  Gate «front coherent gain ≤ 0,5 дБ» меряется на PCM FL/FR и проходит пусто.
- Акустически задние двери на 1–3 мс позади кресла и когерентны: гребёнка и
  оттягивание образа на каждой разрешённой компоненте. Задержка тыла 10–20 мс
  это стандарт любого заводского апмиксера, не «фазовый трюк».
- Бюджет ρ = `max(Rwork, max|a|)`: на горячем мастере без SoundCheck запас для SL
  около нуля, ρ → 0 мгновенно, релиз 50 мс, тыл «дышит» от фронтальных транзиентов.
- Защита лида = один жёсткий ноль на голове 0. Всё, что сепаратор утекает в
  backing/other_vocal/other_unknown, уходит назад на 0,35·p во всю полосу общего
  фида нижнего драйвера и твиттера задней двери. Критерий «protected solo rear
  ≤ −30 дБ» для Q2 ни разу не измерен.
- **Рендерер, который звучал бы правильно, уже написан**: `cabin_balanced`
  с `removal_fraction` и M/S-коррекцией (`c2_scene_renderer.py:130-141`,
  `q2_renderer_native.c:188-194`), но стоит в `bypass` (`c2_scene_renderer.py:44-45`,
  `q2_renderer_native.c:69`) и исключён из release-цепочки как «консервативный
  default».

Virtual Cabin (`tools/soundamp-virtual-cabin/`): точная матрица 6×8 плюс
предполагаемый равномощный fan-out на 16 цепей. Без EQ, кроссоверов, задержек и
акустики; BRIR-путь есть, измерений нет. В loss Q2 не входит, используется только
как амплитудный бюджет безопасности.

### Native / QNX ([runtime audit](UPMIX_RELEASE_RUNTIME_AUDIT.md), `hook/audio/audio_hook.c`)

Проверено: host + ASan/UBSan + QEMU cortex-a15 паритет для common-output,
gain-clock, PCM provider, session chain (≤1,2e-7). Не проверено: любое время на
Krait, RSS, 7200 с soak, реальный EOF.

- Референсный граф 485,1 M MAC/с исключает FFT, 24 WOLA на хоп, признаки, FiLM и
  копии состояния (`q2_local_guidance_model.py:496-500`). Native-ядра держат
  float64-суммы (скаляр VFP на Krait). Адаптер копирует 1,68 МБ состояния на
  каждый вызов плюс ~1,65 МБ цепочка: ~6–7 МБ memcpy на 1024 кадра, нигде не
  посчитано. Измеренный контекст: NEON-оптимизированный HSSR уже 4,3 мс mean /
  9,1 мс max на период 21,3 мс, под нагрузкой Object P99 достигал периода.
  **Референсный профиль на разделяемом ядре нереалистичен; реалистичен только
  student 12/24 (~200 M MAC/с), и он не квалифицирован.**
- В `audio_hook.c` **ноль ссылок на `q2_`**. Не сделано: резерв ring до DSP
  (push дропает/перезаписывает, `:2631-2666`), задержанные packet tags (`:2656-2660`),
  FLUSH/seek/reset/EOF, обход legacy gain/limiter/quantizer (`:3361-3384`),
  click-free handoff, потоки: `spa103_render_frame` держит `spa103_render.lock`
  весь цикл (`:3392`), тот же lock берёт sink peek (`:3648`), 10 мс inference
  заблокирует чтение.
- Три «замороженных» выходных ядра с собственным gain+limiter сосуществуют
  (`q2_common_output`, `q2_renderer_native.c:200-216`, старый `q2_chain_native.c`);
  неверный выбор удвоит лимитер.

**Реальные замеры на Krait существуют** (GCC 8.5 QNX, по SSH на блоке, 512 вызовов
по 1024 кадра, период 21,333 мс, квант таймера ~1,007 мс;

Следствие для бюджета модели: на Krait в этом же тракте безопасно живёт порядка
**200 M MAC/с в int8 или ~100 M MAC/с во float32** плюс 4 хопа FFT1024 с 2 iFFT
на хоп, при условии, что нейросеть идёт через async-worker, как контроллер HSSR,
а не в packet-path под `spa103_render.lock`. Референсный Q2 (485 M MAC/с float +
24 iFFT/хоп) в этот бюджет не помещается; student 12/24 на грани. Q3 mask-net
надо проектировать под ~1 M MAC/хоп int8 и один задний iFFT-пара.

задаёт `AUDIO_STEREO_UPMIX=on`, `AUDIO_STEREO_LFE=assist`; единственный backend
хука это `hssr-universal` (V11), rear 0,25, общий delay 512 кадров, вычитание
принятого тыла из фронта на −3 дБ, шельф +3 дБ выше 4 кГц на Ls/Rs. **Это и
есть реальный baseline, который слышит Luka; Q2 в машине никогда не был.**

**Никто никогда не слушал выход Q2.** Локально ноль отрендеренных WAV.

## 5. Ответы на три вопроса из задания

- **Бэк-вокал и клавишные.** Не выделяются по трём причинам сразу: интерфейс
  подсказок структурно слеп к ним (§3), сепаратор слишком мал и линеен (§4),
  данных 0,62 ч и 0,41 ч в DEV. Углубление детектора не поможет: потолок с
  оракулом это доказывает.
- **Компенсация ошибок декодера.** Реальна, но это симптом аддитивного
  неидентифицируемого разложения. Лечится мультипликативной softmax-маской, не
  коэффициентом.
- **Преимущество над baseline.** Его нет: модель на уровне своего старта.
  Статический по-биновый 2×2 Wiener-фильтр на семейство, подогнанный на TRAIN
  (pooled LS по STFT, та же задержка 1024, ~2–6 k MAC/кадр), по оценке побьёт
  модель на bass/keys/guitar/backing/lead/high_perc на 0,5–4 дБ и сравняется на
  drums. Калибровочный код уже копит суммы по кропам, нужны по-биновые cross/auto
  спектры вместо широкополосных. Этот контроль обязателен в следующем сравнении.

## 6. Текущий эксперимент

Дать закончить, ничего не продлевать. Ожидание: candidate улучшит подсказки для
drums/bass, backing и keys останутся около MUTE, утечка на отсутствующих головах
скорее вырастет (оракул уже показал: absent guitar −24,6 → −15,5 дБ от микса,
absent bass −15,8 → −10,6). Любой исход не оправдывает ещё одну эпоху на этом графе.
После завершения: проверить хеши, снять те же таблицы, что в §2, включая утечку на
отсутствующих головах и β, и закрыть ветку Q2 как диагностику.

## 7. Следующий ограниченный эксперимент: Q3 mask-net

Один запуск, те же данные, цели и скорер, чтобы DEV остался сопоставимым.

1. **Reader**: по-головный допуск с bleed (181 TRAIN / 40 DEV), other_vocal и
   other_plucked в other_unknown, аугментация стемов (gain ±6 дБ, L/R swap,
   полярность, dropout), имитация мастеринга на входе (bus-comp + лимитер + общий
   gain на цели). Закрытие mix = Σ стемов сохраняется.
2. **Модель**: log|X_L|, log|X_R|, ILD, IPD → causal band-split GRU с cross-band
   слоем, ~1 M параметров → per-bin softmax по 12 головам → `mask_k·X`.
   Причинность и 16 мс задержки как сейчас. На runtime синтезируется только тыл.
3. **Loss**: complex MSE + magnitude L1 как сейчас, фиксированный знаменатель,
   UNKNOWN-маски и на аудио.
4. **Обучение на Mac** (M3 Max, MPS работает, torch 2.10), 10–20 эпох, 1–2 дня.
   Bit-exact рестарт не нужен, веса запечатываются хешем после. Данные и
   checkpoints на NAS через SMB `/Volumes/private/Audi/upmix-training-2026-09-11`.
5. **Контроли** на 19 DEV тем же `evaluate_q2_full_source.py`: raw-scalar,
   статический per-bin Wiener, текущий Q2 predicted.
6. **Критерий**: backing и keys NMSE < 0,8 (сейчас 1,06 / 1,84), утечка на
   отсутствующих головах < −30 дБ от микса (сейчас keys −12,8), high_percussion
   < 0,5. Плюс рендер трёх DEV-песен в WAV через цепочку с `cabin_balanced` и
   задержкой тыла 15 мс и **прослушивание до любых выводов**.

Если Q3 не проходит критерий на TRAIN, проверять представление и оптимизацию, не
добавлять эпохи. Если проходит на TRAIN, но не на DEV, сначала данные и
аугментация, потом ёмкость.

## 8. Процесс

- Пятнадцать поколений архитектур (V11 … Q2), 204 runtime-владельца на NAS, и ни
  одна модель не обучалась в режиме, где разделение источников вообще работает:
  сотни или 24 тысячи обновлений на 4-ядерном CPU с моделями до 111 k параметров.
  Самая быстрая машина проекта (M3 Max, 39 ГБ, MPS) не использовалась для
  обучения из-за расхождения 3e-8 между запусками
  ([MPS qualification](UPMIX_Q2_MPS_RESTART_QUALIFICATION.md)). **Узкое место
  не строгость, а скорость итерации.**
- Решение от 2026-09-17: обучение на Mac, файлы на NAS через SMB.
- MoisesDB под CC BY-NC-SA 4.0: для личной машины допустимо, для распространения
  нет. AlbumDB не artist-disjoint.

## 9. Ответы предыдущего агента (2026-09-17, через Luka) и поправки к аудиту

1. **Int8 GEMV на Krait измерялся** (Memora №983): H160 = 186,88 мкс на управление
   при 449 280 MAC → **≈2,4 GMAC/с int8**, только матричное ядро без GRU-нелинейностей,
   FFT и признаков. Первичный stdout не найден, число восстановлено. На float32 не
   переносится. Следствие: Q3 должен выводиться в int8, как HSSR (`vmull.s8` путь в
   хуке уже есть); 1 M MAC/хоп int8 ≈ 0,4 мс GEMV на хоп, то есть ~8 % ядра до FFT и
   нелинейностей. Ориентир Q3: ≤1–1,5 M MAC/хоп int8.
2. **Baseline CPU всего `dio_manager` при CarPlay без апмикса не существует.** Открытое
   измерение, нужен интервальный замер на блоке.
3. **`cabin_balanced` не отвергался прослушиванием.** Консервативный integration
   default; электрические сравнения C2 с removal 0 / 0,35 / 0,70 есть
   ([C2](UPMIX_C2_SCENE_REFERENCE.md):54), прослушивания нет. Ни «хуже», ни «точно
   правильно» не установлено. Поправка к §4: формулировку «звучал бы правильно»
   читать как «единственный кандидат, который стоит послушать».
4. **Запрета Luka на задержку/декорреляцию тыла нет.** Требование: не получать эффект
   только громкостью, реверберацией или фазовыми манипуляциями. Исторический HQ-кандидат
   имел задержку тыла 1024 сэмпла при незадержанном фронте
   ([AUDIO_5_1_STATE](AUDIO_5_1_STATE.md):783), в машине контролируемо не слушался.
   Задержка тыла 10–20 мс в Q3 допустима как эксперимент.
5. **Выход обученного Q2 никто не слушал.** Поправка к §4: на NAS есть 64 WAV
   (`R/q2-role-review-packets-a/attempts/*/preview-NN.wav`), это оригинальные стемы
   для разметки, плюс C1/C2 reference-рендеры; результата Q2 среди них нет.
6. **Whole-song exclusion был осознанным консервативным отбором, не доказанно лучшим.**
   Эксперимента против bleed-песен с масками нет. Поправка к §7: при по-головном
   допуске нормированное распределение carrier/softmax требует явной обработки
   неполных целей (неизвестная голова не супервизируется, но остаётся в нормировке).
7. **MPS отклонён по контракту bit-exact restart.** Два непрерывных CPU-запуска уже
   расходились на 3e-8. Для Q3 отдельный контракт недетерминированного обучения:
   сохранять веса/optimizer/RNG, проверять resume относительно повторных запусков.
8. **Состав нагрузки в loaded-прогоне hssr-object невосстановим.** Тот прогон это
   свидетельство чувствительности к конкуренции, не воспроизводимый эталон.

Дополнительно: замороженный front-fidelity gate требует проверки и PCM, и J525-proxy
(не только неизменного FL/FR); для кандидата эта проверка не выполнена.
