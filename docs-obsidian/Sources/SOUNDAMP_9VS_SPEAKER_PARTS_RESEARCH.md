## Два динамика задней двери — один усиленный выход

| Сторона | Общий выход дверных ВЧ + НЧ | Отдельный выход surround |
|---|---|---|
| Левая | T38/4,5 → R14 + R15 | T38/27,35 → R209 |
| Правая | T38/16,17 → R16 + R17 | T38/28,36 → R210 |

Итого сзади, без сабвуфера: шесть физических динамиков и четыре усиленных
выхода. Два драйвера двери нельзя независимо направлять из upmix. Два логических
входа Ls/Rs также не дают четырёх независимых команд этим выходам J525.
Проводка не устанавливает точные пассивные фильтры или акустическую полярность.

В текущем [JSON](../../tools/soundamp-virtual-cabin/audi_a5_f5_9vs_3d_off.json)
эта электрическая топология уже есть. Распределение логического rear bus между
дверью и surround по равной суммарной энергии — тестовое предположение, не
восстановленная заводская настройка. Число драйверов нельзя превращать в
коэффициент громкости или просто удваивать энергию дверного выхода.

## Что дают публичные измерения, а чего не дают

Автор Bobby Kinstle опубликовал собственные измерения системы B9 S4:
[описание метода](https://www.audizine.com/threads/complete-guide-of-speakers-in-the-b9-b-amp-o-system.858483/),
[таблица, вкладка Rear door](https://docs.google.com/spreadsheets/d/1ftkRt8rz1ZgtTtAs-NRYAIkHbtRuhX2cu702CeuqhVs/edit?gid=1070674348#gid=1070674348).
Таблица открыта и просмотрена в Chrome, без редактирования.

Он описывает параллельное подключение дверных динамиков, номинал каждого 4 Ω,
ограничение снизу около 160 Гц усилителем и фильтрующий конденсатор твитера.
Это первичные любительские данные по S4, не спецификация Audi для данного S5.
Мощность автор частично оценивает предположительно. Точные частоты среза,
импедансные кривые, ёмкость конденсатора, чувствительность и направленность
данной машины остаются неизвестными.

Вывод для исследования: задний «bass loudspeaker» нельзя заранее считать
сабвуфером без вокального диапазона. Публичные данные дают основание проверять
существенную СЧ-составляющую двери. Значения 160 Гц и 4 Ω допустимы лишь как
неподтверждённый сценарий, не как фиксированная заводская калибровка S5.

## Ревизия железа и параметризация имеют значение

[Audi TSB 2052251/4 от 25.06.2020](https://static.nhtsa.gov/odi/tsbs/2020/MC-10176853-0001.pdf)
охватывает B&O S5 Sportback 2018–2019. Audi связывает описанные искажения с
параметром усилителя, допускающим перегрузку динамика. Процедура включает
проверку/обновление J525, а при подтверждённой неисправности — замену сабвуфера
или обоих передних НЧ. Исходные `8W5035297` и обновлённые `8W5035297A` нельзя
смешивать слева/справа по этой процедуре.

Это не диагноз данной машины и не рекомендация что-либо прошивать. Одного SW
`0420` недостаточно для установления применимости сервисного действия.

### Уточнение после проверки SoundAmp в тот же день

Данные параметризации не отсутствуют: они уже есть в
`/Users/luka/Desktop/AUDI_2/Firmwares/SoundAmp/`. В предоставленном EEPROM-дампе
`uPD70f3479_8W0035465_0420_H11/S-25C640A@TMSOP8.BIN` (8192 байта) непосредственно
проверены строки `4TU-00120.07.163JA20162` по смещению `0x0004` и `8W2909510A`
по `0x0124`. Это идентификаторы в сохранённом дампе, не новое чтение текущего
состояния усилителя машины.

CodeFlash размером `0x180000` содержит A07 по `0x100000`, B01 по `0x120000`
и полный встроенный SHARC boot/application stream по `0x041014..0x068777`.
SHA-256 CodeFlash:
`8776fdb84d05571cf4addf42655bc875da7c47cc35166e3cee6c60bc5841fe4b`.
Оба существующих теста извлечения SHARC повторно прошли; проверяются хеши и
разбор всех 560 блоков. См. [разбор извлечения](SHARC_APPLICATION_EXTRACTION.md).
Файл `Config_24082026_172036.bin` имеет всего 5 байт; считать его полным
акустическим dataset по одному имени нельзя.

Следующий приоритет — расшифровать применение имеющихся данных: банк/состояние,
фильтр, логическая шина, физический выход T38. Для этого не требуется сначала
добывать отсутствующий образ SHARC: он уже извлечён. Неизмеренная акустика
динамиков и салона остаётся отдельной задачей.

Старый `SoundAmp/AMP_AUDIO_DSP_TUNING.md` содержит полезные адреса и выгрузки,
но также устаревшие утверждения: PR 9VD вместо данного 9VS, выдвижные твитеры,
противоречивую трактовку таблицы `0x97028`. Его акустические назначения
коэффициентов нельзя целиком переносить в virtual cabin без проверки
потребляющего кода. CSV селекторов EEPROM — не таблица уже прочитанных gain.

## Приоритеты улучшения upmix — предложения, не выполненные изменения

1. Сначала исправить оценку утечки: получить управляющие маски, панорамы и
   коэффициенты ограничения из полного микса, затем заморозить их для анализа
   стемов. Отдельные адаптивные прогоны vocals/instruments не измеряют вклад
   этих стемов в обработанном миксе. Нелинейный остаток учитывать отдельно.
2. Развести перенос исходного объекта из фронта и формирование rear-ambience.
   Сейчас общий rear до ВЧ-полки участвует в вычитании из фронта. Удаляемый
   сигнал должен сохранять исходную панораму источника; декоррелированный фон
   и новое заднее позиционирование требуют отдельной логики.
3. Расширить проверочный renderer ветвями физических драйверов: выход J525 →
   дверной НЧ/ВЧ через отдельные передаточные функции; surround отдельно.
   Сохранить границу между доказанной матрицей, известной проводкой и
   неизвестной акустикой. Неподтверждённые фильтры проверять диапазоном сценариев.
4. Оценивать rear-vocal leakage по частотам и местам прослушивания, а не только
   по суммарной цифровой энергии Ls/Rs. Текущая полка +3 dB / 4 kHz действует
   на логические rear-сигналы, а не адресно на дверные твитеры; фактический эффект
   по драйверам зависит от дальнейшей обработки J525.
5. После достоверной оценки добавить cabin-aware критерий выбора/дообучения.
   Сейчас обучение HSSR не пропускает результат через акустический салон.
   До измерений проверять устойчивость к неопределённым фильтрам/задержкам;
   после измерений — использовать отклики канал→место при 3D/Symphoria OFF.
   Не обучать модель выдавать недоказанную акустику за точную.
