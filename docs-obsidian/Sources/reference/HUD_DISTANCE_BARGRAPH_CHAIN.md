# Дистанция и bargraph в проекции HUD

Дата: 2026-09-11. Продолжение [исследования VC](DISTANCE_BARGRAPH_CHAIN.md).

**Графический код HUD умеет отправить на отрисовку дистанцию и шкалу в одном
проходе. Проверено исполнением оригинального ARM-кода двух прошивок.**
Это отличается от найденного в VC `hmi_app.elf` предиката, который напрямую
проверяет `BargraphOn` и скрывает число.

Это не утверждение, что штатная цепочка BAP уже разрешает оба элемента на
реальном HUD. Участок, преобразующий навигационные данные в пакет для GDC,
в этом исследовании не восстановлен. Нельзя выдавать проверку renderer за
готовое решение для всего тракта.

## Проверенные образы и адреса

Корень: `/Users/luka/Desktop/AUDI_2/Firmwares/HUD/extracted/`.

| Прошивка | Блок | SHA-256 |
|---|---|---|
| `FL_8W6919617G_1952_APPL_V000` | FD_61 | `0146bfb0ac3584f3f6fe19f2d38a97c65f3bbd4bbed63d2d43c51db24bf4dc63` |
| та же | FD_62 | `259409a247a297417d6b398bb42a9f51897514604f320c0b184ccb92b53c35ee` |
| `FL_8W6919617M_2325_APPL_V000` | FD_61 | `8a71ffd31fdfc17131507e0d259bd216751ec2c7918468b8e18ba58787198fc1` |
| та же | FD_62 | `81a31aa257ef322d3333f2e10770d3edb32179abff75e0bd904689503007449b` |

FD_61 — сырой образ GDC, ARM32 little endian, исследованные функции в ARM mode.
FD_62 — данные сцен. В обеих версиях `.GraphicsDrawTask.text` отображается
из FD_61 file offset `0x12debc` в runtime VA `0x808f5000`, размер `0x2329b4`.
Смещение функции: `0x12debc + (VA - 0x808f5000)`.
Секция целиком различается в 14 байтах, но проверенный участок walker/selector
`[0x13259c, 0x133e44)` совпадает. Дерево страниц FD_62
`[0x1294, 0x114a68)` побайтно одинаково.

Сопутствующий MCU FD_51 имеет архитектуру V850/RH850, не ARM.
Старый `HUD_ANALYSIS.md` содержит ошибочные обобщения архитектуры и предположения
о номерах BAP-функций; они не использовались как доказательство этой цепочки.
Существующая Ghidra-база FD_51 загружена с base=0, а поздние локальные заметки
устанавливают link base=0x20000: адреса из неё нельзя смешивать с runtime VA.

## Что читает GDC

Графическая задача принимает внутренний пакет, а не восемь байт NavSD FctID 18:

```text
навигационные данные → [преобразователь пакета: не установлен]
  → внутренний пакет GDC
      packet[8]       — страница
      packet[9..12]   — маска включённых групп
      packet[13]      — дополнительные биты групп
      packet[13+field] — селекторы элементов
  → GraphicsDrawTask → обход сцены → отрисовка ресурсов
```

Проверенные функции:

| Runtime VA | File offset FD_61 | Назначение |
|---|---|---|
| `0x808f96e0` | `0x13259c` | Обход страниц/групп; тело в `0x808f96e4` |
| `0x808f9e68` | `0x132d24` | Dispatch элемента по kind; тело в `0x808f9e6c` |
| `0x808fa750` | `0x13360c` | Отрисовка до шести числовых символов; тело в `0x808fa754` |
| `0x808fae9c` | `0x133d58` | Чтение селектора по field/type/mask; тело в `0x808faea0` |
| `0x808fa984` | `0x133840` | Передача surface descriptor в графический тракт |

Адреса начала включают `mov ip, sp` перед прологом. Старая IDA-база отделила
некоторые такие инструкции в самостоятельные функции; для исполнения нужен
полный вход, а не только адрес тела.

### Дистанция

На странице 3 числовые элементы находятся в группах **9** и **14**:
узлы FD_62 `0x943a8` и `0x95524`, kind=3, base field=28.
Они используют шесть nibble-селекторов из `packet[41..44]`.
Селектор 15 означает пропуск символа.

Единица измерения — отдельный элемент (`0x9465c` / `0x957d8`),
младшие четыре бита `packet[41]`. Внутренний selector 0 не рисует единицу,
selector 1 выбирает ресурс `r0691` «m». Это **другая нумерация**, чем BAP unit=0
для метров. Нельзя переслать BAP payload в GDC как готовый пакет.

В `HudDrawNumericGlyphsBody` (`0x808fa754`) нет чтения поля шкалы.
Группа должна быть включена, а селекторы должны содержать действительные цифры.

### Шкала

Группа **2**, узел FD_62 **`0x8f3e4`**, kind=0, field=32:
уровень читается из **`packet[45]`**. Есть 17 состояний, 0–16.
Каждое содержит 16 поверхностей сегментов. Selector 17 уже вне таблицы:
этот элемент не выдаёт ни одного сегмента.

Это внутренний уровень 0–16, а не непосредственно BAP процент 0–100.
Включение группы чисел не зависит от этой группы и от значения field 32.

В коде также есть особая обработка cached/composite graphics, kind=1/5/6.
Флаги по `0x6e3658`/`0x6e3656` нельзя называть BAP BargraphOn:
их вычисление относится к выбранным поверхностям и дублирующему графическому слою.
Исследованные числовые узлы kind=3 через эти проверки не проходят.

## Проверка исполнением оригинального кода

Скрипт [`tools/verify_hud_distance_bargraph.py`](../../../tools/verify_hud_distance_bargraph.py)
загружает оригинальные FD_61 и FD_62, проверяет оба SHA-256 и исполняет
ARM page walker, group/element dispatch, selector, numeric glyph positioning.
Подменены только конечная подача поверхности, memcpy и вспомогательная
регистрация поверхности. GLES, оптическое преобразование и устройство
не эмулируются.

На каждой из двух прошивок прошло **108 сценариев**:
2 числовые группы × 18 значений шкалы × 3 состояния числового представления
(«150», пустые цифры, группа выключена). Всего **216**.

| Вход во внутренний renderer | Число | Единица | Шкала |
|---|---:|---:|---:|
| Дистанция 150 m, bar selector 0–16 | 3 glyph surfaces | 1 | 16 segment surfaces |
| Дистанция 150 m, bar selector 17 | 3 | 1 | 0 |
| Цифры заменены selector=15, bar 0–16 | 0 | 1 | 16 |
| Группа дистанции выключена, bar 0–16 | 0 | 0 | 16 |

Тест проверяет идентичность ресурсов цифрам 1, 5, 0 и их порядок по x.
В примере позиции (x, y, width, height):

- `1`: `(80, 79, 15, 23)`;
- `5`: `(95, 79, 15, 23)`;
- `0`: `(110, 79, 15, 23)`;
- `m`: `(127, 89, 17, 12)`;
- сегменты шкалы: x=159, width=11.

В этом примере штатные координаты числа/метров и шкалы не пересекаются.
Остальные единицы, величины, варианты размещения и оптический вывод этим
примером не покрыты.

Логи и декомпиляция:
`output/r2/hud-distance-bargraph-2026-09-11/{G-1952.json,M-2325.json,ida-gdc-functions.json}`.
Исходные flash-блоки не изменялись; IDA-сессия закрыта без сохранения изменений
базы. Пояснения и восстановленные сигнатуры сохранены в JSON-экспорте.

## Что это меняет в плане совместного показа

Если на автомобиле HUD заменяет число шкалой, проверенный GDC-код допускает,
что переключение уже выражено во входных данных: выключена группа 9/14 либо
цифры стали selector=15. **Какой именно вариант формирует штатный путь и где,
пока не доказано.** Не установлена связь BAP BargraphOn с этой маской/селекторами.

Для обоих штатных элементов HUD нужно сохранить одновременно:
включённую группу дистанции, цифры/единицу и действительный уровень шкалы.
В этом renderer отдельная правка вида «убрать `!bargraphOn`» не найдена и для
проверенного сочетания элементов не требуется.

Наш `maneuver_render` выводит кадр в VC. Добавление числа туда решает задачу
только для VC; оно не добавляет число в проекцию. Правка предиката VC также
не изменяет HUD. Выключение BAP-флага шкалы нельзя считать решением для
одновременной дистанции и шкалы на обоих устройствах.

Следующий участок для полной цепочки — producer внутреннего GDC-пакета:
проследить записи маски групп 9/14 и полей 28–32 при изменении NavSD FctID 18,
или сопоставить захваты пакетов непосредственно до и после появления шкалы.
Без этого нельзя назвать точный HUD-патч или гарантировать решение только на ГУ.
