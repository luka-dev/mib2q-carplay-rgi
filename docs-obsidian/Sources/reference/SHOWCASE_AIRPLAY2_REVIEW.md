# Сравнение с Showcase, airplay2 и airplay2-receiver

Дата: 2026-09-11. База репозитория: `6fe1aa0` плюс исправления предыдущего
[прохода CatPlay](CATPLAY_REVIEW_FIXES.md). Все изменения этого прохода находятся
в рабочем дереве; на ГУ не развёрнуты.

## Подтверждённые ошибки и исправления

Все пять замечаний относятся к восстановлению/непрерывности видео, приоритет P2.

| Триггер | Ошибка до исправления | Исправление и проверка |
| --- | --- | --- |
| Новая avcC-конфигурация во время текущего соединения | `av_sink_frame` обновлял кэш SPS/PPS, но при уже выставленном `fedConfig` не отправлял их в OMX. | Новая конфигурация повторно подаётся с `OMX_BUFFERFLAG_CODECCONFIG`; следующий picture должен быть IDR. Тест проверяет новые байты и флаги реального вызова `OMX_EmptyThisBuffer` через подставной компонент. |
| Access unit содержит SPS/PPS и IDR вместе | `_HasParameterSet` классифицировал весь пакет как конфигурацию, ветка `!isConfig` пропускала подачу самого кадра. | Сканирование различает parameter sets, picture NAL и IDR. Смешанный пакет целиком подаётся как кадр. Тест включает трёх- и четырёхбайтовые start codes. |
| OMX отклоняет входной буфер либо кадр превышает его вместимость | `_FeedInput` возвращал `void`, отказ терялся, а зависимые P-кадры продолжали поступать. Отсутствовала обратная связь к хуку. | Ошибка проходит через sink в decoder worker: очередь зависимых кадров очищается, сокет получает `shutdown`, reader закрывает соединение. Хук использует существующее восстановление с config + IDR. Проверены отказ OMX, слишком маленький буфер, EOF и отбрасывание очереди. |
| Декодер не стартовал или был пересоздан после ошибки | На следующем входном P-кадре код мог создать новый декодер, подать сохранённую конфигурацию и сразу этот P-кадр без опорного IDR. | Потеря непрерывности заканчивает соединение; новый декодер/конфигурация имеют явный IDR-gate. Блокирующий send мог выйти за этот deadline. | Сокет остаётся неблокирующим. Регрессия проверяет настоящий `F_GETFL`, а также EAGAIN, POLLOUT и ошибки отправки. |

Основной код: [sink_omx_qnx.c](../../../altscreen_render/sink_omx_qnx.c),
[main.c](../../../altscreen_render/main.c),
[altscreen_av.c](../../../hook/altscreen/altscreen_av.c).

Для ошибок конфигурации выполнено одинаковое воспроизведение на исходном и
исправленном коде: config A, config B, SPS/PPS + IDR. Раньше OMX получал **один**
пакет длиной 11 байт; теперь получает **три**, последний — целиком 17 байт.

Рабочий поток проверяет поколение перед отключением транспорта. Задержавшаяся
ошибка прежнего decoder generation не очищает очередь и не закрывает новое
соединение. На стороне рендерера worker делает только `shutdown`; `close`
остаётся за reader, чтобы номер fd не переиспользовался во время чтения.

## Различия, которые не следует переносить как исправления

- Showcase использует двухбайтовую inclusive length + 12-byte RTP для buffered
  audio. Наш подтверждённый захватами APAP имеет BE32-inclusive length и
  15-байтовый header с 24-битным sequence. Замена формата или ширины sequence
  по этому эталону сломала бы действующий тракт.
- Showcase screen decrypt использует ChaCha20-Poly1305 с AAD из header.
  Наш type-111 путь получает ключ/IV и AES-CTR-примитивы от штатного 210.81.
  Это разные согласованные варианты защиты, а не основание менять cipher.
- Pairing, RTSP transport и основная сессия принадлежат штатной libairplay.
  Их нельзя заменять сервером Swift/Python без отдельной смены архитектуры.
- Семантика полного TEARDOWN с пустым/отсутствующим streams уже исправлена
  предыдущим проходом и согласуется с Showcase и штатным исходником Apple.
- Получение/хранение buffered rate, anchor и flush уже проверено предыдущим
  аудитом iOS/Pioneer. Переход на упрощённый 16-битный RTP flush Showcase
  непригоден для нашего APAP.

## Проверки

- Полный `sh scripts/run_tests.sh` прошёл, включая новые `altscreen_sink_test`
  и `altscreen_worker_test`, предыдущие регрессии и APAC на приватном захвате:
  3980 аутентифицированных кадров, 3977 byte-identical APAC-пакетов, 64 декодированы.
- Оба новых теста и `altscreen_av_test` прошли AddressSanitizer/UBSan.
- Clang Static Analyzer для QNX sink и decoder worker — без замечаний;
  `make -C altscreen_render hostcheck` прошёл.
- `LOG=0 bash scripts/build_hook.sh` прошёл: 26 разрешённых interpose-экспортов,
  проверки ABI/runtime/emutls сохранены. `bash scripts/build_renderers.sh`
  прошёл: ARM ELF, emutls=0. BSP link использует предусмотренные build-скриптом
  import stubs; это проверка сборки, не выполнения GPU/OMX на ГУ.
- Независимая проверка против Monocypher из локального Showcase: 1000 Poly1305,
  5000 ChaCha20, включая перенос 32-битного счётчика, и 4000 APAP AEAD decrypt
  с проверкой обоих AAD. Для каждого AEAD-пакета проверено отклонение изменённого
  тега без записи plaintext. Использованы синтетические данные.
- Совпадение с IETF-вариантом при nonce `[0,0,0,0] + nonce8` также подтверждено.
  Исправлен неверный комментарий «would authenticate nothing»: для короткого
  пакета эти состояния совпадают. Рабочая криптография не менялась.

## Открытые вопросы и проверка на ГУ

Синхронизация presentation по sender timestamps остаётся архитектурным
различием: Showcase передаёт timestamp и учитывает RespectTimestamps, наш
hook → renderer протокол передаёт только длину и Annex-B. Buffered audio
сохраняет anchor, но воспроизводится через FIFO/QSA. Это уже отмечено в
[аудите buffered lifecycle](IOS_26_1_BUFFERED_AUDIO_LIFECYCLE_AUDIT.md).
Этот проход не доказал, что различие является причиной конкретного сбоя;
для изменения планирования нужен захват arrival/PTS/presentation на ГУ.

Проверить на автомобиле: старт карты, быстрый replug, обновление конфигурации,
перезапуск рендерера, временный отказ OMX/выходной поверхности и возврат с
новым IDR. Особенно проверить отсутствие цикла переподключений и сохранение
ограничения попыток запуска OMX. Host-тесты подставляют результаты OMX, но
не декодируют через настоящий Qualcomm-компонент.
