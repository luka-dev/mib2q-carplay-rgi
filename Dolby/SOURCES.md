# Источники и следующий этап проверки

## Основной первичный источник

[Dolby PC Entertainment Experience v4 — официальный white paper](https://professional.dolby.com/siteassets/pdfs/dolby-pc-entertainment-experience-v4-white-paper.pdf)

Локальная копия: `documents/Dolby-PCEE-v4-white-paper.pdf`.

- Страница 6: Surround Decoder — стерео → 5.1/7.1; дальнейший вывод в Surround Virtualizer.
- Страница 7: Surround Virtualizer — HRTF для встроенных динамиков и наушников.
- Ограничение: старое поколение Dolby PCEE v4, не спецификация текущего Dolby Access.

## Контекст современных форматов

[Microsoft: Spatial Sound](https://learn.microsoft.com/en-us/windows/win32/coreaudio/spatial-sound)

Описывает Windows Spatial Sound, статические и динамические звуковые объекты, поддержку Dolby Atmos для наушников и домашнего кинотеатра. Сам по себе не подтверждает автоматический апмикс двухканального Spotify в виртуальное 7.1.

[Dolby Atmos for Mobile Devices](https://professional.dolby.com/categories/mobile/dolby-atmos-for-mobile-devices/)

Описывает применение HRTF к пространственной информации и получение стереосигнала для наушников. Это контекст бинаурального рендеринга, не доказательство схемы Windows Dolby Access.

[Dolby Atmos for the Home Theater](https://professional.dolby.com/siteassets/tv/home/dolby-atmos/dolby-atmos-for-home-theater.pdf)

Описывает объектное аудио, работу рендерера ресивера и способы передачи Atmos. HDMI/MAT и рендеринг для наушников — разные пути обработки.

## Локальные первичные данные

Файлы из установленного пакета Dolby Access исследованы только чтением. `binary-findings.json` содержит исходные пути, размеры, хеши и смещения обнаруженных строк, чтобы находки можно было воспроизвести.

Отсутствие слова `upmix` в строках DLL не доказывает отсутствия алгоритма: он может называться Surround Decoder, быть статически скомпонованным или не иметь диагностических строк. Наличие названия функции тоже не доказывает её вызов в текущем профиле.

Сообщения форумов про стерео противоречат друг другу; они не использованы как доказательство конкретной цепочки.

## Как проверить дальше

1. Установить значения `surround_decoder_enable` и stereo bypass в реально работающем профиле, если их можно получить через диагностику/трассировку установленной версии.
2. Для проверки поведения подавать контролируемые двухканальные сигналы и сравнивать результат при изменении одной настройки. Изолировать тест от других звуков и автоматического переключения профилей, сохраняя и восстанавливая исходные параметры.
3. Проверить точку захвата: loopback до обработки эффекта не показывает окончательный сигнал наушников.
4. Различие выходных сигналов доказывает обработку, но не обязательно внутреннее число каналов. Для строгого утверждения «2.0 → 7.1» нужны внутренние параметры/буферы либо документация именно этой реализации.

Такие измерения в рамках текущего исследования не проводились.
