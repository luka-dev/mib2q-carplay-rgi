# Dolby stereo → surround: синтез, остаток и атаки

Продолжение [FINDINGS.md](FINDINGS.md), 2026-09-20. Исследован
`Dolby/DolbyAudioProcessing.dll`, PE32+ AMD64, image base `0x180000000`, SHA-256
`0fada40251880d03c657a357745d362799c93fb6024f733f1c8bf1057f5e4715`.
Адреса ниже — VA при этой базе; RVA и файловые смещения в `verified-map.json`.

Существенная новая проверка: оригинальные x64-функции выполнены в Unicorn
на контролируемых комплексных входах. Windows-компонент целиком не запускался.
Это проверка вычислительных ядер; активный профиль Dolby Access, полный
PCM-тракт и физические назначения всех выходов пока не установлены.

## Восстановленный тракт

```text
77 комплексных бинов L/R
    │
    ├─ статистика 20 полос → направление и сила выделения
    │                        │
    ├─ направленная часть → два выбранных выхода → фазовые повороты
    │
    └─ остаток L/R → [2 потока либо 5 с задержками] → матрица распределения
                                                       │
                        сумма направленной части и остатка
                                                       │
                        маршрутизация и общий gain ≈ +1 dB
```

Основные функции:

| VA | Установленное назначение |
|---|---|
| `0x18004d0b0` | Статистика полос, энергетическая история, детектор атаки |
| `0x18004e1c0` | Индекс направления 0…1023 |
| `0x18004e2c0` | Коэффициенты направленной части и остатка |
| `0x180031410` | Анализ пары, выбор/смешивание матриц остатка |
| `0x180031860` | Синтез пары, сборка перечисленных операций |
| `0x18004e510` | Направленный сигнал и два остаточных потока |
| `0x18004eb70` | Повороты комплексного сигнала на ±90° |
| `0x18004d6d0` | Добавление распределённого остатка к выходам |
| `0x18005a9f0` | Три дополнительных потока из задержанных остатков |

В синтезе существует также условный вызов `0x18004df60`; его полный эффект
в этом этапе не восстановлен. В тесте полного синтеза эта ветка отключена.

## 1. Что отделяется от стереосигнала

В каждой полосе суммируются энергии и действительная часть взаимного
произведения: `EL=Σ|L|²`, `ER=Σ|R|²`, `C=ΣRe(L·conj(R))`.
Сглаживаются `S=EL+ER`, `D=EL−ER`, `C` по правилу
`Xnew=(1−α)Xold+αXcurrent`. Коэффициент α свой для каждой полосы.

Игнорируя малую защитную добавку к знаменателю, вычисление остатка
можно записать так:

```text
Δ = sqrt(D² + 4C²)

P = [ (Δ+D)/(2S)      C/S       ]
    [      C/S       (Δ−D)/(2S) ]

residual = (I − P) · [L, R]ᵀ
```

Математически `P` — проектор на главное направление вещественной матрицы
ковариации, умноженный на `q=Δ/S`. Его собственные значения `q` и 0.
Поэтому при слабой направленности извлечение частичное. Даже при `C=0`
неравенство энергий L/R может создавать направленную часть.

Направление соответствует приблизительно `atan2(2C,D)`, квантованному на
1024 позиции по кругу. Таблица секторов задаёт два выхода и коэффициенты
смешивания. Численно проверены формулы из первого отчёта, включая множитель
16 при применении коэффициентов и множитель 2 для остаточных коэффициентов.

## 2. Куда попадают простые сигналы

Для конфигурации `0x1802eccc0` локальные выходы `[0,1,2,3,4]`
маршрутизируются в глобальные слоты `[0,2,1,4,5]`.
Их функциональные роли по тестам: левый, центр, правый и пара surround.
Физическое именование этой пары в Windows ещё не доказано.

Результат направленной ветки до общего gain, при заданной стационарной
статистике, на один комплексный бин:

| Вход L, R | Индекс | Ненулевые глобальные выходы | Остаток |
|---|---:|---|---|
| `1, 0` | 0 | слот 0 ≈ 1 | ≈ 0 |
| `0, 1` | 512 | слот 1 ≈ 1 | ≈ 0 |
| `1, 1` | 256 | слот 2 ≈ 1.414214 | ≈ 0 |
| `1, −1` | 768 | слоты 4,5 ≈ `j·0.733881` | ≈ 0 |
| `1, j` | 0 | нет | `1, j` |

Последний тест — равномощная квадратурная пара с нулевой действительной
корреляцией, не случайный шум. Его остаток затем слышен на выходах через
матрицу распределения.

Фазовые коды пяти локальных выходов `[0,0,0,+1,−1]` означают
умножение направленного сигнала на `[1,1,1,+j,−j]`.
Остаток добавляется **после** этих поворотов. Поэтому утверждение
«весь surround просто сдвигается на 90°» было бы неверным.

Прочитаны четыре конфигурации: 2→6, 2→8, ещё одна 2→8 и 2→10.
Их локальные таблицы, фазовые коды и маршруты сохранены в `kernel-probes.json`.
Внешний обработчик применяет `1.122018456` (около +1 dB) к активным выходам.
Этот gain не включён в численные результаты тестов выше.
Глобальный слот 3 не входит в маршруты данной пары; это не доказывает
отсутствия отдельного формирования LFE в полном тракте.

## 3. Как распределяется остаток

В упрощённом режиме два остаточных потока смешиваются следующей матрицей
для пяти локальных выходов базовой конфигурации:

```text
left      =  0.692244 R0
center    =  0.203954 R0 + 0.203954 R1
right     =               0.692244 R1
surroundA =  0.681228 R0 − 0.123005 R1
surroundB = −0.123005 R0 + 0.681228 R1
```

Следовательно, остаток подаётся также во фронт и центр.
Исходная функция `0x180031860` проверена с этим режимом по всем 77 бинам
для каждой из четырёх конфигураций, включая SIMD-циклы и скалярные хвосты.
Режим двух потоков был принудительно задан тестовым заголовком; это не
доказательство выбора именно этого режима в пользовательском профиле.

В режиме пяти потоков первые два сохраняются, ещё три строятся так:

```text
V2[k,t] = R0[k,t−dA[k]] + R1[k,t−dB[k]]
V3[k,t] = R0[k,t−dC[k]] + R1[k,t−dA[k]]
V4[k,t] = R0[k,t−dB[k]] + R1[k,t−dC[k]]
```

Их вместе с R0/R1 смешивает матрица размером `число_выходов × 5`.
Задержки различаются по бинам; каждый найденный tap проверен импульсом.

| Бины, с нуля | Максимальная задержка, вызовов ядра |
|---|---:|
| 0…9 | 31 |
| 10…18 | 19 |
| 19…30 | 11 |
| 31…40 | 7 |
| 41…76 | 3 |

Для последних 36 бинов `dA=1`, `dB=2`, `dC=3`.
Суммарно кольца содержат 791 слот с комплексными L/R, плюс область зеркала
для обхода границы. Истинная задержка равна значению таблицы +1, поскольку
чтение предшествует записи текущего входа. Перевод в миллисекунды пока
не выполнен: нужно доказать период вызова ядра.

## 4. Что происходит на резких атаках

Для каждой полосы имеется отдельная медленная история энергии H:
`Hnew=βH+(1−β)Ecurrent`. Детектор сравнивает текущую энергию с прежней H:

```text
target = clamp(0.501716673 · log2_approx(0.501187205 · Ecurrent/H), 0, 1)
wnew = target, если target > wold; иначе β·wold
```

В реальном коде присутствуют малые защитные добавки к энергиям.
Идеальный log2 дал бы линейное изменение target от 0 до 1 на участке
примерно +3…+9 dB. Оригинальная аппроксимация даёт при +4 dB `0.161997`,
при +6 dB `0.500128`, при +8 dB `0.833992`, при +9 dB `1`.
Проверены 9 уровней роста во всех 20 полосах.

Вес w смешивает две матрицы остатка по нормированной формуле:

```text
b = sqrt(1−w²)
M = (w·Mtransient + b·Msteady) / sqrt(1 + 2ρwb)
```

Для базовой матрицы пяти потоков `ρ=0.8339375854`.
Например, её прямой коэффициент R0→left меняется `0.549643 → 0.848888`,
R0→center `0.256050 → 0.395452`, R0→surroundA `0.540897 → 0.209838`.
Остальные коэффициенты тоже изменяются; обе полные матрицы сохранены в JSON.
Их эффект согласуется с уменьшением пространственного размазывания атак;
это интерпретация назначения, а сами коэффициенты и переключение проверены.

В конфигурации 48 kHz `β=0.9816858768`; последовательность «стационарный
сигнал → скачок амплитуды ×4 → прежний сигнал» дала веса
`0, 1, β, β², β³`. Формула смешивания матриц подтверждена оригинальной
`0x180031410` для каждого из 20 диапазонов.

## 5. Частотные группы и границы доказанного

Для конфигурации 48 kHz границы групп, исключающие верхний индекс:
`[2,4,5,7,10,12,14,15,17,18,20,22,24,27,30,34,40,46,54,77]`.
Для 44.1 kHz:
`[2,4,5,7,10,12,14,15,17,18,20,22,25,28,31,36,42,48,58,77]`.
Таблицы α и частотные значения из конфигураций также извлечены в JSON.
Назначение частотных значений как центров либо границ полос пока не доказано.

Следующий этап: восстановить банк анализа/синтеза и период вызова,
собрать полный PCM→PCM стенд, проверить переключение режимов двух/пяти
остаточных потоков и ветку `0x18004df60`, затем связать глобальные слоты
с физическими каналами и отдельным басовым трактом. Пока нельзя объявлять
полностью воспроизведённый Dolby Surround или подтверждённый Atmos-профиль.

## 6. Сравнение с нашим HSSR и приоритет улучшений

Дополнение 2026-09-21 по обсуждению с Luka. Сравнение относится к текущим
локальным исходникам HSSR; состав сборки и параметры в автомобиле отдельно
не проверялись. Основания: [hssr_dsp.c](../../../hook/audio/hssr_dsp.c),
[hssr_dsp.h](../../../hook/audio/hssr_dsp.h),
[stereo_upmix.c](../../../hook/audio/stereo_upmix.c) и
[stereo_upmix.h](../../../hook/audio/stereo_upmix.h).

Пока нет измеренного или прослушанного доказательства, что Dolby лучше HSSR
в целом. Исполнение отдельных ядер Dolby подтверждает их математику, но
не заменяет сравнение полного звукового тракта при одинаковой громкости.

| Задача | Разобранный участок Dolby | Наш HSSR |
|---|---|---|
| Выделение направления | Энергии и действительная корреляция в 20 полосах; адаптивная проекция | 32 полосы управления, побиновый пространственный анализ и сопровождение объектов |
| Защита вокала и баса | В найденном ядре семантическое распознавание не обнаружено; это не вывод обо всей DLL | Обученные маски защиты; качество зависит от ошибок модели |
| Пространственный фон | Остаток после направленной проекции; матрицы двух/пяти потоков и задержки по бинам | Диффузный слой, фазовые повороты; в scene-сборке задержка тыла 12 мс, поведение зависит от режима |
| Атаки | Детектор роста энергии меняет матрицу распределения остатка | Анализ атак и сглаживание масок; аналог найденного переключения остаточных матриц не установлен |
| Центр и фронт | Выделение центрального сигнала, распределение остатка также во фронт | Цифровой C оставлен нулевым, центр формирует Audi; предусмотрено управление сохранением сигнала во фронте |

Число полос само по себе не определяет качество. Предварительная гипотеза:
Dolby может давать более равномерное обволакивание, а HSSR — лучше отвечать
задаче «лид впереди, отдельные партии второй сценой сзади». Оба предположения
требуют прослушивания; наша защита может как удерживать нужный лид, так и
чрезмерно подавлять инструменты либо пропускать вокал назад.

### Двух механизмов Dolby недостаточно

Распределение остатка с учётом атак и задержки по частотам — перспективные
дополнения, но они не закрывают все причины потери качества. Нужны три
согласованных этапа:

1. **Выделение остатка.** В Dolby это `(I−P)[L,R]`, оставшееся после
   направленной проекции. Наш диффузный слой и материал, разрешённый
   семантической маской для тыла, не эквивалентны этому остатку. Сначала нужно
   проверить, что именно мы распределяем: утечку вокала задержки разнесут
   по пространству, а не исправят.
2. **Баланс фронта и тыла после усилителя.** Следует согласовать извлечение,
   вычитание из фронта и подачу назад. Избыточное вычитание может опустошать
   фронт, сохранение копий — усиливать дублирование и интерференцию. Audi
   повторно смешивает входные каналы, поэтому оценивать только PCM6 до
   усилителя недостаточно. Независимый `front_retention` уже реализован;
   его наличие не означает, что оптимальная настройка найдена. См.
   [проверку сохранения фронта](../../../docs/UPMIX_GUARD_RETENTION_2026-09-20.md).
3. **Формирование пространственного фона.** После первых двух этапов можно
   оценивать матрицы остатка, реакцию на атаки и задержки по частотам.
   Возможный выигрыш — обволакивание и сохранение чёткости атак; возможная
   цена — размазанность и дополнительная окраска при смешивании каналов.

Приоритет исследования: **выделение → баланс после усилителя →
декорреляция и атаки**. Полная замена HSSR на основании найденных функций
не обоснована. Разумный следующий эксперимент — сохранить нашу защиту
вокала и независимо проверить обработку атак и частотно-зависимые задержки:
базовый вариант, только атаки, только задержки, оба механизма вместе.
Сравнивать на одинаковых фрагментах, с выровненной громкостью и одним трактом
Audi, оценивая утечку лида, сохранность фронта, чёткость ударных и характер
тыла. Этот эксперимент предложен, но в рамках данного разбора не выполнен;
превосходство Dolby и величина выигрыша не установлены.

## Воспроизведение

Из корня workspace:

```sh
python3 output/r2/dolby-surround/reproduce.py
python3 output/r2/dolby-surround/probe_decoder.py
```

Зависимости: Capstone для дизассемблирования; Unicorn и NumPy для проб.
Probe проверяет SHA-256 и выполняет только выбранные ядра без Windows API.
Проверки завершились успешно: 800 случайных случаев статистики/конфигураций,
20 спектральных проб, 462 импульсных пути задержек, две конфигурации
сглаживания по два кадра, четыре проверки синтеза пары, переход матриц
и 180 случаев детектора атаки. Это не проверка всех ветвей DLL.
