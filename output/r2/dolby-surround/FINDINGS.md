# Dolby Surround Decoder: первый разбор вычислительного пути

**Продолжение:** [SYNTHESIS.md](SYNTHESIS.md) — синтез и маршрутизация,
остаточные матрицы, задержки и детектор атак, проверенные исполнением
оригинальных ядер в Unicorn. Раздел «Что ещё не установлено» ниже отражает
состояние первого статического этапа; актуальные ограничения — в продолжении.

Исследован локальный `Dolby/DolbyAudioProcessing.dll`, PE32+ AMD64,
little-endian, preferred image base `0x180000000`.
SHA-256: `0fada40251880d03c657a357745d362799c93fb6024f733f1c8bf1057f5e4715`.
Версия `7.3.7.rel` указана в сопровождающих исходных материалах папки.
Анализ статический; DLL не запускалась, настройки Windows не менялись.

Найден связанный путь от именованного параметра Surround Decoder до
вычисления статистики пары каналов, индекса направления и коэффициентов
смешивания. Существенный результат: эта реализация использует адаптивную
обработку по 20 группам комплексных отсчётов, а не только постоянную матрицу.
Трактовка групп как частотных полос следует из обхода комплексных бинов по
таблице границ; конкретный банк анализа/синтеза ещё не восстановлен.

## Связь параметра с DSP

`CDapVRModule::ApplyRunTimeParams` начинается с VA `0x18011cd60`.
В блоке `0x18011d5ec`–`0x18011d727`:

- `params+0x5b4` — признак наличия обновления;
- `params+0x5b5` — значение включения;
- в callable помещается адрес `0x180004190`;
- вызов через `0x1801291f0` передаёт состояние DSP и целое значение;
- соседняя диагностическая строка — `dap_vr_surround_decoder_enable_set: %d`.

Setter `0x180004190` нормализует значение как `value != 0`, записывает
`state+0x780` и устанавливает `state+0x13b0 = 1` при изменении.
Функция `0x180003590` переносит это значение в `state+0x77c`.
Обработчики `0x180007d10` и `0x18002c2b0` проверяют рабочий флаг.
В первом проверка находится по VA `0x18000850f`; кроме флага проверяются
значение 2 в регистре счётчика/режима и дополнительные условия конфигурации.
Точные типы всех полей входного буфера ещё не установлены.

При выбранной конфигурации вызывается `0x1800217c0` с состоянием из
`state+0x13b8`. Оттуда вызывается анализатор пары `0x180031410`.

```text
ApplyRunTimeParams
  → surround_decoder_enable_set (0x180004190)
  → pending +0x780 → active +0x77c
  → условный вызов 0x1800217c0
      → анализ пары 0x180031410
          → статистика 20 полос 0x18004d0b0
          → индекс направления 0x18004e1c0
          → коэффициенты 0x18004e2c0
```

## Что вычисляется

`0x18004d0b0` вызывает `0x180022640` отдельно для двух входов.
Внутри последней суммируются квадраты двух компонентов каждого комплексного
отсчёта. Затем первая функция суммирует попарные произведения компонентов
двух входов. В математической записи для одной полосы:

```text
EL = Σ (Lre² + Lim²)
ER = Σ (Rre² + Rim²)
X  = Σ (Lre·Rre + Lim·Rim) = Σ Re(L·conj(R))
```

Обозначения L/R условные: это два входа выбранной пары. Точное соответствие
системным каналам нужно окончательно проверить по таблицам маршрутизации.

В цикле `0x18004d37f`–`0x18004d51f` обновляются три массива по 20 float:

```text
S[b] = (1-α[b])·S[b] + α[b]·(EL[b]+ER[b])  // state +0x00
D[b] = (1-α[b])·D[b] + α[b]·(EL[b]-ER[b])  // state +0x50
C[b] = (1-α[b])·C[b] + α[b]·X[b]           // state +0xa0
```

Здесь state — состояние анализатора пары, не верхнеуровневое DAP state.
Код также обнуляет очень малые значения и ведёт отдельные массивы
энергетической истории и управляющего коэффициента (`+0xf0`, `+0x140`).
Значения α и временные постоянные пока не извлечены.

`0x18004e1c0` берёт `2·C[b]` и `D[b]`, вызывает `0x18005b150`, затем
преобразует результат в дискретный индекс таблицы. По структуре кода
`0x18005b150` — кусочно-полиномиальная аппроксимация
`atan2(y,x)/(2π)`: отношение меньшего модуля к большему, поправки четверти
оборота/полуоборота и знака. Это вывод по инструкциям, исходного имени нет.
Таким образом, направление зависит одновременно от различия энергий и
межканальной взаимной составляющей:

```text
direction[b] ≈ atan2(2·C[b], D[b]) / (2π)
```

Отрицательное значение заворачивается добавлением 1, затем идут масштаб
32768, преобразование в целое, насыщение int16 и сдвиг на 5 бит.
По индексу выбирается участок таблицы (`0x18005b120`).

В `0x18004e2c0` дополнительно вычисляется, с защитной добавкой ε:

```text
u = C / (2·(S+ε))
v = D / (4·(S+ε))
r = sqrt(u²+v²)
```

Значения `r+v`, `r-v`, `u` и коэффициенты из выбранной таблицы участвуют
в формировании матриц. Также сохраняются величины, эквивалентные
`0.5-(r+v)`, `0.5-(r-v)`, `-u`.
Интерпретация: выделение направленной части и остатка, зависящее от
статистики сигнала. Полный синтез выходов ещё нужно проследить;
названия direct/ambient здесь были бы рабочими гипотезами.

## Конфигурации и surround boost

В выбранной ветке найдены структуры со следующими начальными полями:

| VA | Первые два uint32 | Число анализируемых пар |
|---|---|---|
| `0x1802eccc0` | 2, 6 | 1 |
| `0x1802eccf0` | 2, 8 | 1 |
| `0x1802ecd20` | 2, 8 | 1 |
| `0x1802ecd50` | 2, 10 | 1 |

Выбор этих структур по входному количеству и целевой конфигурации
соответствует путям 2→6, 2→8 и 2→10. Однако называть их автоматически
5.1, 7.1 и 7.1.2 пока нельзя: роль LFE и порядок каналов не восстановлены.

`surround_boost_set` сопоставлен с `0x180004120` по тому же wrapper-паттерну.
Он ограничивает целочисленный параметр диапазоном 0…96, масштабирует
константой около `0.0004807692312`, сохраняет pending `+0x7ac`.
Commit переносит значение в `+0x7a8`; обработчик использует его около
`0x180009604` и передаёт в `0x180023300`.
Это отдельный параметр; его единицы и полный эффект пока неизвестны.

## Что ещё не установлено

- Активен ли данный путь в текущем профиле Dolby Access на Windows.
- Имена, порядок выходных каналов и точный путь LFE.
- Границы 20 полос в Гц, длина преобразования и задержка.
- Полные матрицы синтеза, декорреляция, обработка переходов и связь с HRTF.
- Возможность отдельно вызвать DLL для получения многоканального PCM.

Следующий конкретный этап: разобрать таблицы от `0x1802eae80` и
маршрутизацию от `0x1802ed2b0`, затем `0x180031860` / `0x18004e510`,
чтобы связать найденные коэффициенты с конкретными выходными буферами.
После этого имеет смысл измерять L=R, L=-R, только L и некоррелированную
пару через контролируемый тестовый тракт.

## Воспроизводимость

`reproduce.py` читает DLL и сохраняет дизассемблирование Capstone плюс
`verified-map.json` с SHA-256, VA, RVA и файловыми смещениями.
В `*.asm` также сохранены использованные листинги radare2.
Названия внутренних функций в отчёте назначены по поведению; это не
экспортированные символы. Публичные экспорты DLL — только
`DllCanUnloadNow` и `DllGetActivationFactory`.
