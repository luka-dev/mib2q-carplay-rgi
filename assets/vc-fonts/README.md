## Подтверждённые кандидаты

Пересечение пяти Audi-шрифтов — 668 Unicode-кодов. Следующие варианты имеют прямые cmap-записи во всех пяти, без зависимости от CJK fallback:

| Назначение | Вариант | Unicode | Замечание |
| --- | --- | --- | --- |
| Простое обрамление | `[Exit 12]` | U+005B / U+005D | ASCII, две скобки занимают 2 байта UTF-8 |
| Компактное обрамление | `‹Exit 12›` | U+2039 / U+203A | Одинарные угловые кавычки; 6 байт на пару |
| Более заметное обрамление | `«Exit 12»` | U+00AB / U+00BB | Двойные угловые кавычки; 4 байта на пару |
| Другие скобки | `{Exit 12}` / `(Exit 12)` | ASCII | Прямое покрытие |
| Разделитель | `◆` / `◊` | U+25C6 / U+25CA | Закрашенный ромб / незакрашенный lozenge |
| Приблизительное время | `≈ 37 min` | U+2248 | Знак приблизительного равенства, **не часы** |
| Прибытие + длительность | `≈ 22:42 \| 37 min` | U+2248 | Предложение для большой сцены, не реализовано |
| Стрелки | `← ↑ → ↓ ↖ ↗ ↘ ↙` | U+2190–2193, U+2196–2199 | Есть в шрифтах; пользователь ранее просил убрать текстовую стрелку |
| Прочие | `… • · ► ◀ ▯ ▪` | см. каталог | `►` U+25BA — не то же самое, что `▶` U+25B6 |

Пользователь утвердил `‹…›` для SignPost/Exit и затем `◌` для времени; они внедрены локально (см. статус в начале). `◎` и `≈` — предыдущие варианты, не используются.

В случае внедрения нужно резервировать **байты UTF-8** выбранного обрамления в лимите CurrentPositionInfo (сейчас 96 байт); нынешний резерв 2 байта подходит только для ASCII `[]`. Проверить усечение без разрыва кодовой точки и закрывающую скобку.

## Чего не найдено / важные ловушки

- Во всех Unicode cmap девяти контурных шрифтов не найдено символов с Unicode-именами CLOCK, WATCH или HOURGLASS. В частности, отсутствуют U+231A `⌚`, U+231B `⌛`, U+23F0–23F3 `⏰⏱⏲⏳`; угловые сектора часов U+25F4–25F7 также отсутствуют. Это не исключает отдельные графические ресурсы часов в UI, но их нельзя считать доступными символами текстового поля.
- `⟦ ⟧`, `⟨ ⟩`, `⌈ ⌉` не имеют прямого покрытия Audi. `【 】`, `「 」`, `『 』` встречаются в CJK-шрифтах, но их доступность в конкретном европейском навигационном виджете не подтверждена.
- U+223C `∼` отсутствует в Audi; ASCII `~` и U+2248 `≈` — другие, доступные символы.
- U+25C7 `◇` не следует путать с имеющимся U+25CA `◊`.
- В Audi-шрифтах private-use U+F8FF с именем глифа `apple` **рисует четыре кольца Audi**, что проверено рендером. Системный шрифт macOS на том же коде может нарисовать логотип Apple. Ориентироваться на PNG, не на обычный текст чата.
- U+E000–U+E003 обычных AudiTypeDisplay — специальные стрелки, не часы; в High-вариантах их нет. U+F000 в High — служебная метка, не часы. Остальные private-use включают альтернативные цифры и знак параграфа.
- Наличие глифа, не привязанного к cmap, само по себе не даёт Unicode-символа для передачи через BAP. Их имена/ID также сохранены в JSON.

Идеи для теста, не внедрены: `◈ Exit 12 ◈`, `❖ Exit 12 ❖`, `◉ 22:42`. Последний — графический маркер, не часы и не стандартное обозначение ETA. U+F8FF с кольцами Audi доступен непосредственно в Audi-шрифтах, но по смыслу не заменяет ETA.

Прицельно проверены и **не найдены ни в одном из девяти контурных шрифтов**: `⚑ ⚐ ⚓ ⚙ ⚡ ✈ ✉ ✦ ✧ ✪ ❯ ❮ ⌖ ⌂ ☺ ☻ ➜ ➤ 🏁 📍 🎯 🚗`, а также часы из раздела выше. Цветные картинки из системного emoji-шрифта macOS не являются свидетельством покрытия VC.

## Углублённый поиск часов

Диагностический скрипт: `clock_followup.py`. Java/JAR/прошивка не изменены.

1. Дополнительно просмотрены все private-use глифы арабского и китайского шрифтов: [Arabic](previews/LT_Univers440_88perc_Arabic-private-use.png), [ZYHei](previews/ZYHei_GB18030_c-private-use.png). В арабском есть специальные значки U+E200–E202 (не часы), далее цифры и диакритика; в китайском — пунктуация и письменные знаки. Часов на этих листах нет.
2. Декодирован bitmap Arial: [каталог 557 кодов](catalogs/arial-bitmap.json), [полное изображение](previews/arial-bitmap-all.png). `GLYP` offset 0xC0, payload 1118 = 4 + 557*2; коды — отсортированные уникальные uint16 LE. `RWFM` offset 0x227A содержит размеры 9206×34; `RWD4` offset 0x22A6 содержит 156502 = 9206*34/2 байт, по два 4-битных пикселя в байте, старшая половина первой. Все шесть chunk-записей точно покрывают файл. SHA-256 распакованного файла: `8308e59073430a99899f5d14bb8028a31fc3fe4c14295b2112391501e7a62273`. Визуально просмотрен весь bitmap: в том числе его private-use область отображает пустые прямоугольники, не часы. Первые строки bitmap содержат служебные отметки; они сохранены, не приняты за часть рисунка глифа.
3. В атласе интерфейса **найдены и извлечены настоящие изображения секундомеров**: [лист изображений](previews/clock-images.png), [источники/SHA/смещения/координаты](clock-images.json).

| Ресурс | Атлас / UID | Размер | Что действительно нарисовано |
| --- | --- | --- | --- |
| `lap_timer/intervalWatch.png` | full LA / 221 | 32×34 | Секундомер с выделенным сектором |
| `lap_timer/stopwatch.png` | full LA / 223 | 32×34 | Секундомер |

Для двух исследованных `.atlas`: magic `TC\0`, count offset 43, `BIN\0` offset `47+count*8`. BIN имеет 32-байтный заголовок после magic; затем count записей `<I4f2H>` (UID, относительные ширина/высота, x/y, пиксельные ширина/высота). Проверены все 9/517 записей: размеры по UV совпадают с пиксельными. Затем идут LA-пиксели (2 байта на пиксель); последующий хвост формата для этой задачи не интерпретировался. Извлечённые четыре картинки просмотрены визуально, размеры и границы проверены. Это структурный разбор именно этих файлов, не универсальная спецификация всех версий атласов.

**Вывод:** стандартного либо private-use текстового символа часов не найдено. Две иконки выше существуют как графические ресурсы, а не Unicode-глифы. Атласный UID 223 нельзя считать U+00DF или иным кодом для BAP. Связь этих картинок с текстовым кодом CurrentPositionInfo не установлена; текущая передача строки сама по себе не выбирает atlas sprite. Использование настоящей картинки потребовало бы отдельной работы с UI/ресурсами VC, не просто замены строки в нашем JAR.

`◎` (U+25CE) — два концентрических круга / bullseye, не часы; имеет cmap-запись в JP/KR/ZYHei, но не в Audi. Это отклонённый в пользу `◌` кандидат. Обрамление `‹…›` имеет прямое покрытие всех Audi-начертаний; новый текст внедрён локально уже после исследования, физическая проверка ещё впереди.

## Font lookup (.lur)

Скопированы восемь Audi `.lur` в `lookup-resources/`, структура каждого проверена в [lookup-ranges.json](lookup-ranges.json):

- magic `lur\0`;
- с offset 4: little-endian `uint16 version`, `uint32 font_slot_count`, `uint32 range_count`;
- offset 14: записи по 6 байт, `uint16 first`, `uint16 last`, `uint16 font_slot`;
- интервалы включительные, отсортированы, без пересечений; длина файла точно `14 + range_count * 6`, все slot ID в пределах объявленного числа.

Это структурная интерпретация. Точное соответствие числовых слотов конкретным файлам и выбранному UI-виджету здесь не доказано.
Например, в `AudiTypeDisplayHigh_Normal_EU_Arabic.lur` кавычки и `≈` направлены в slot 0, а диапазон с U+23F1 — в slot 3. **Попадание в диапазон .lur не доказывает наличие глифа**: диапазоны шире реальных cmap. По одной .lur нельзя объявлять поддержку часов.
